## Prompt 工程

### Q1. 【单选 · 基础 · 必会】 zero-shot、one-shot、few-shot 提示的核心区别在于？

- A. 只影响生成速度
- B. 仅在微调时才使用
- C. 是否提供示例：zero 无示例、one 给 1 个、few 给多个示例  ✅
- D. 模型参数量不同


**答案**：C　**解析**：三者指推理时是否提供任务示例；示例能显著提升复杂任务的遵循度与格式一致性。

### Q2. 【多选 · 进阶 · 必会】 下列哪些属于常见的高级 Prompt 技巧？

- A. 角色设定（system persona）  ✅
- B. 少样本示例（few-shot）  ✅
- C. Chain-of-Thought（思维链）  ✅
- D. 增大 max_tokens 即可提升推理


**答案**：A、B、C　**解析**：CoT、角色设定、少样本都是经典提升技巧；增大 max_tokens 只是放宽输出长度，不属于提示技巧。

### Q3. 【单选 · 进阶 · 必会】 Chain-of-Thought（思维链）提示的主要作用是？

- A. 加快 token 生成速度
- B. 强制模型只输出 JSON
- C. 减少上下文长度
- D. 让模型分步推理，降低复杂任务出错率  ✅


**答案**：D　**解析**：CoT 引导模型显式写出中间推理步骤，把复杂问题拆解为可验证子步骤，显著提升算术/逻辑/多跳推理准确率。

### Q4. 【单选 · 基础 · 必会】 系统提示（System Prompt）与用户提示（User Prompt）的主要区别是？

- A. 系统提示只在微调时有效
- B. 用户提示优先级更低
- C. 两者完全等价
- D. 系统提示设定角色/规则/边界，用户提示承载具体任务  ✅


**答案**：D　**解析**：系统提示在对话最前定义模型身份与全局规则；用户提示是每轮具体请求，系统提示通常优先级最高。

### Q5. 【判断 · 基础 · 必会】 Prompt 越长，模型输出质量一定越高。

- A. 正确
- B. 错误  ✅


**答案**：B　**解析**：提示过长会引入噪声、稀释关键指令、挤占上下文，反而可能降低质量；质量取决于清晰度与结构。

### Q6. 【单选 · 进阶 · 进阶必会】 面对 Prompt 注入攻击，下列哪种做法是有效的缓解手段？

- A. 完全禁止任何用户输入
- B. 把外部文本直接拼进系统提示以提升相关性
- C. 仅依赖增大 temperature
- D. 隔离并标注不可信外部内容，并对输出做约束与护栏  ✅


**答案**：D　**解析**：注入靠“劫持指令”生效；隔离不可信内容、标注来源、输出约束与最小权限工具授权是核心防线。

### Q7. 【单选 · 进阶 · 必会】 结构化输出（JSON Mode / Function Calling）在应用开发中的核心价值是？

- A. 提升模型参数规模
- B. 让模型产出可被程序直接解析的确定格式  ✅
- C. 缩短上下文窗口
- D. 替代所有自然语言交互


**答案**：B　**解析**：结构化输出避免脆弱的正则抽取，是 LLM 接入下游逻辑、数据落库与工具调用的关键接口。

### Q8. 【多选 · 进阶 · 必会】 关于“好的 Prompt”，下列说法正确的有？

- A. 复杂任务可配示例  ✅
- B. 指令清晰、目标明确  ✅
- C. 给出必要格式与约束  ✅
- D. 越长越好、信息越堆越多越稳


**答案**：A、B、C　**解析**：清晰指令、格式约束与适度示例是高质量提示的共性；冗长堆砌反而稀释信号。


## LLM 应用开发基础

### Q9. 【单选 · 基础 · 必会】 调用 LLM API 时，temperature 参数主要控制什么？

- A. 计费单价
- B. 输入 token 上限
- C. 输出的随机性/多样性  ✅
- D. 最大输出长度


**答案**：C　**解析**：temperature 越高输出越随机多样，越低越确定保守；0 适合需要稳定性的任务。

### Q10. 【单选 · 基础 · 必会】 关于 LLM 的 token，下列说法正确的是？

- A. token 只统计输出不计输入
- B. 一个汉字固定等于一个 token
- C. token 是模型处理文本的最小单位，计费与限流通常按 token 计  ✅
- D. token 数量与字符数永远相等


**答案**：C　**解析**：token 是分词后的最小单元，API 一般按输入+输出 token 计费并设总量上限。

### Q11. 【单选 · 基础 · 必会】 什么是流式输出（streaming）？为什么聊天应用普遍使用它？

- A. 会显著降低生成质量
- B. 一次性返回完整结果以节省带宽
- C. 逐 token 返回，降低首字延迟、提升交互体验  ✅
- D. 仅用于离线批处理


**答案**：C　**解析**：流式让服务端边生成边推送，首字时间（TTFT）大幅缩短；底层常基于 SSE 或 WebSocket。

### Q12. 【判断 · 进阶 · 必会】 max_tokens 参数限制的是单次请求中模型生成的最大输出 token 数。

- A. 正确  ✅
- B. 错误


**答案**：A　**解析**：以 OpenAI 等主流 API 为例，max_tokens 指 completion 上限；输入长度另由模型上下文窗口约束。

### Q13. 【多选 · 进阶 · 必会】 应用层处理 LLM 速率限制（rate limit）的正确做法包括？

- A. 对可幂等请求才重试  ✅
- B. 忽略限流直接高频请求
- C. 指数退避+抖动重试  ✅
- D. 并发限流（令牌桶/信号量）  ✅


**答案**：A、C、D　**解析**：限流需退避重试、并发控制与幂等判断；对不可幂等请求重试可能放大副作用。

### Q14. 【单选 · 基础 · 必会】 什么是上下文窗口（context window）？超出会发生什么？

- A. 每次会话的固定费用
- B. 用户界面的宽度
- C. 模型单次能处理的最大 token 数；超出会被截断或报错  ✅
- D. 训练数据集大小


**答案**：C　**解析**：上下文窗口是输入+输出 token 的总容量上限；超出时旧内容被截断或请求被拒，需靠截断/摘要/外部记忆解决。

### Q15. 【多选 · 进阶 · 进阶必会】 关于 top_p 与 temperature，下列说法正确的有？

- A. top_p 控制最大输出长度
- B. top_p 按累积概率截断候选词集（核采样）  ✅
- C. temperature 缩放 logits 改变分布  ✅
- D. 两者通常不必同时拉到极高  ✅


**答案**：B、C、D　**解析**：top_p 是核采样阈值，temperature 是分布温度；输出长度由 max_tokens 控制。

### Q16. 【判断 · 进阶 · 必会】 temperature=0 时，同一 prompt 多次调用结果一定完全一致。

- A. 正确
- B. 错误  ✅


**答案**：B　**解析**：即便 temperature=0，部分实现仍存在非确定性（并行采样、量化、服务端负载），只能说高度可复现。

### Q17. 【多选 · 进阶 · 进阶必会】 LLM 调用缓存在哪些场景适用？

- A. 模板化生成  ✅
- B. 对时效性不敏感的知识问答  ✅
- C. 幂等且结果稳定的请求  ✅
- D. 含用户私有/实时数据的请求


**答案**：A、B、C　**解析**：缓存适合稳定、非实时、可幂等的内容；含私有/实时数据的请求禁止缓存以防串味与越权。


## Embedding 与向量检索

### Q18. 【单选 · 基础 · 必会】 什么是 Embedding（嵌入向量）？它如何表示语义？

- A. 仅用于图像压缩
- B. 把文本按字符编码成 ASCII
- C. 与词袋模型完全相同
- D. 把文本映射为稠密向量，语义相近的文本向量距离更近  ✅


**答案**：D　**解析**：Embedding 把文本投影到高维连续空间，语义相似的样本在空间中邻近，支持基于距离的语义检索。

### Q19. 【多选 · 进阶 · 必会】 常见的向量相似度度量包括？

- A. 词频差
- B. 余弦相似度  ✅
- C. 欧氏距离  ✅
- D. 点积  ✅


**答案**：B、C、D　**解析**：余弦衡量方向一致性、点积衡量方向与幅度、欧氏衡量绝对距离；选哪种取决于是否归一化及是否关注模长。

### Q20. 【判断 · 基础 · 必会】 Embedding 维度越高，语义表示一定越好。

- A. 正确
- B. 错误  ✅


**答案**：B　**解析**：维度需与训练任务匹配；过高易过拟合且浪费算力，更关键的是模型质量与对齐方式。

### Q21. 【单选 · 进阶 · 必会】 向量数据库相比传统关系型数据库的核心差异是？

- A. 原生支持近似最近邻（ANN）检索而非精确等值/范围查询  ✅
- B. 完全不支持事务
- C. 不支持任何索引
- D. 只能存储字符串


**答案**：A　**解析**：向量库针对高维向量的相似性搜索做了专用索引（HNSW、IVF 等）；传统关系库擅长结构化查询。

### Q22. 【多选 · 挑战 · 进阶必会】 下列哪些是主流向量数据库/方案及其适用场景？

- A. 向量数据库不能和 SQL 共存，必须彻底替换关系库
- B. pgvector 适合已用 Postgres、复用事务与 SQL 的中小场景  ✅
- C. Pinecone 是托管 Serverless 方案，运维省心  ✅
- D. Milvus/Qdrant/Weaviate 适合自建大规模检索  ✅


**答案**：B、C、D　**解析**：方案各有侧重；pgvector 等证明向量能力可内嵌于关系库，并非非此即彼。

### Q23. 【单选 · 挑战 · 进阶必会】 为什么大规模向量检索普遍采用 ANN（近似最近邻）而非精确 KNN？

- A. ANN 不需要任何索引
- B. KNN 无法并行
- C. ANN 结果永远比 KNN 更准
- D. 精确 KNN 随数据量超线性变慢，ANN 以可接受精度损失换数量级加速  ✅


**答案**：D　**解析**：精确 KNN 在亿级向量下开销不可接受；ANN（HNSW、IVF-PQ）通过图/聚类索引快速逼近 Top-K，是 RAG 在线检索基石。

### Q24. 【多选 · 挑战 · 进阶必会】 关于 HNSW 索引，下列说法正确的有？

- A. 是一种精确最近邻算法，结果零误差
- B. 分层可导航小世界图，查询从稀疏顶层贪心下降到底层精搜  ✅
- C. 建图内存占用大、写入/删除较贵  ✅
- D. 召回高、查询快  ✅


**答案**：B、C、D　**解析**：HNSW 用图索引换取速度与召回，代价是内存与写放大；它仍是近似而非精确算法。

### Q25. 【判断 · 进阶 · 选修】 向量检索只能用于文本，不能用于图像或音频。

- A. 正确
- B. 错误  ✅


**答案**：B　**解析**：多模态嵌入模型（如 CLIP）能把图像/音频编码到同一向量空间，同样可做相似检索与跨模态搜索。

### Q26. 【单选 · 进阶 · 进阶必会】 对向量做 L2 归一化后，余弦相似度等价于？

- A. 曼哈顿距离
- B. 点积  ✅
- C. 欧氏距离平方的一半
- D. 汉明距离


**答案**：B　**解析**：归一化后向量模长为 1，余弦相似度 = 两向量点积；这也是很多向量库要求先 normalize 再只用点积加速的原因。


## RAG 检索增强生成

### Q27. 【单选 · 基础 · 必会】 RAG（检索增强生成）主要解决了 LLM 的哪些问题？

- A. 仅解决中文支持
- B. 知识滞后、幻觉、私有数据不可达  ✅
- C. 模型参数量不足
- D. 训练速度慢


**答案**：B　**解析**：RAG 在生成前先检索权威/私有文档注入上下文，缓解知识截止、减少无依据幻觉，并让模型用到私域数据。

### Q28. 【多选 · 进阶 · 必会】 标准 RAG 流程通常包含哪些阶段？

- A. 生成（generation）  ✅
- B. 增强（augmentation，拼入上下文）  ✅
- C. 模型重新训练
- D. 检索（retrieval）  ✅


**答案**：A、B、D　**解析**：RAG 是推理期流程：检索→拼入提示增强→交给 LLM 生成；不涉及训练/微调。

### Q29. 【多选 · 进阶 · 必会】 关于文档切分（chunking），下列说法正确的有？

- A. 按标题/语义递归切分更友好  ✅
- B. 固定长度切分实现简单但可能割裂语义  ✅
- C. 滑动窗口重叠可缓解边界割裂  ✅
- D. 切得越大越好，越多上下文越准


**答案**：A、B、C　**解析**：粒度太小丢上下文、太大引噪声；重叠可缓解边界问题，但都需结合检索器与任务调节。

### Q30. 【判断 · 进阶 · 必会】 RAG 中检索到的文档越多，最终答案一定越准确。

- A. 正确
- B. 错误  ✅


**答案**：B　**解析**：过多无关片段会稀释关键信号、挤占上下文并放大噪声，反而降低质量；需配合重排与相关性阈值。

### Q31. 【多选 · 挑战 · 进阶必会】 Advanced RAG 相对 Naive RAG 常用的优化手段包括？

- A. 上下文压缩  ✅
- B. 查询改写/扩展  ✅
- C. 混合检索（向量+关键词）  ✅
- D. 重排序（rerank）  ✅


**答案**：A、B、C、D　**解析**：从检索前后两头优化：query 侧改写、召回侧混合、精排侧 rerank、送入侧压缩，全面提升相关性与信噪比。

### Q32. 【单选 · 挑战 · 进阶必会】 RAG 中的重排序（rerank）用于解决什么问题？

- A. 替代向量数据库
- B. 对初召回结果按相关性二次精排，提升送入 LLM 的片段质量  ✅
- C. 仅用于图像生成
- D. 压缩模型参数量


**答案**：B　**解析**：向量召回侧重速度、精度有限；rerank 模型（如 cross-encoder）对 query-doc 联合打分，精排出 top 片段。

### Q33. 【单选 · 挑战 · 进阶必会】 混合检索（hybrid search）相比纯向量检索的优势是？

- A. 检索速度一定更慢不可用
- B. 只能用于英文
- C. 结合语义向量与关键词（BM25）互补，兼顾意图与精确匹配  ✅
- D. 完全不需要向量


**答案**：C　**解析**：向量擅长语义泛化但弱于专名/编号精确匹配；BM25 反之。混合检索用 RRF 等融合两者，适合含术语的知识库。

### Q34. 【多选 · 挑战 · 进阶必会】 评估 RAG 检索质量常用的指标包括？

- A. Hit Rate（命中率）  ✅
- B. MRR（平均倒数排名）  ✅
- C. 模型显存占用
- D. NDCG  ✅


**答案**：A、B、D　**解析**：离线可用命中率、MRR、NDCG 衡量片段相关性；显存占用不是检索质量指标。

### Q35. 【单选 · 进阶 · 进阶必会】 RAG 中知识库没有答案时，较稳妥的做法是？

- A. 检索得分低于阈值时提示模型明确拒答，避免强行编造  ✅
- B. 直接返回随机片段
- C. 无论如何都要生成一个答案
- D. 关闭检索只用模型参数记忆


**答案**：A　**解析**：阈值/相关性兜底让模型“知之为知之”；强行编造会放大幻觉，是 RAG 落地常见坑。

### Q36. 【判断 · 基础 · 必会】 RAG 必须依赖向量数据库，不能用传统数据库做检索。

- A. 正确
- B. 错误  ✅


**答案**：B　**解析**：RAG 本质是“检索+生成”，检索可用关键词、SQL、图谱或混合方案；向量库只是常见的语义检索实现。

### Q37. 【多选 · 挑战 · 选修】 GraphRAG 相比传统 RAG 更擅长的场景是？

- A. 跨文档的全局归纳与主题总结  ✅
- B. 完全取代向量检索
- C. 回答需要聚合大量文档的宏观问题  ✅
- D. 单一片段内的精确事实抽取


**答案**：A、C　**解析**：GraphRAG 先抽取实体/关系构建知识图谱，擅长全局归纳；局部事实抽取仍可由传统 RAG 完成，二者可互补。

### Q38. 【多选 · 挑战 · 进阶必会】 RAG 的上下文压缩（context compression）技术包括？

- A. 用 LLM 对小片段摘要后再拼接  ✅
- B. 把整个知识库原样塞入上下文
- C. 只保留与 query 最相关的句子（extractive）  ✅
- D. rerank 后仅截取 top  ✅


**答案**：A、C、D　**解析**：压缩聚焦关键证据、减少冗余与噪声；原样全塞会撑爆窗口并稀释信号。


## Function Calling / 工具调用

### Q39. 【单选 · 基础 · 必会】 什么是 Function Calling（函数调用）？它与普通文本生成的区别？

- A. 模型输出结构化“调用某函数的请求”，由应用执行后回传结果  ✅
- B. 模型直接在内部运行代码

### Q68. 【单选 · 挑战 · 选修】 多头注意力（Multi-Head Attention）的作用是？
