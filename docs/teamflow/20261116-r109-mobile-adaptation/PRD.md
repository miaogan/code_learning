# r109 · 移动端适配走查与修复

## 用户目标

承接 r108（跃迁档案看板），用户要求「继续做，特别是移动端的前端适配」。对刚落地的新页面与全站关键页面做真实窄屏走查，修复影响可用性的适配问题。

## 已确认范围

- 在 360 / 390 / 430 三档真实视口走查 `/leap`、`/`、`/report`、`/interview`、`/exam`、`/practice`。
- 修复发现的触控目标缺陷：筛选 chip 在移动端未达 44px 触控下限。
- 走查结论与截图证据沉淀到任务夹与 `logs/teamflow/r109-mobile/`（后者 gitignore）。

## 非目标

- 不改桌面布局（≥1024 零变化）。
- 不改既有可拖拽悬浮按钮（太傅 FAB）的交互设计、不改顶部导航横滑范式（两者是全站既有约定）。
- 不动全站 token 语义与既有样式行（base.css / tokens.css 仅 append）。
- 不提交、不推送、不部署。

## 验收标准

1. 360/390/430 三档下 `document.scrollWidth === clientWidth`（无整页横向溢出）。
2. 筛选 chip（笔试/练习/学习的方向、子方向、难度、语言等）在 ≤640 视口渲染高度 ≥44px。
3. /leap 三块内容在窄屏无溢出、无截断、无重叠。
4. 前端 typecheck / lint / test / build 全绿；桌面布局零回归。
