# r78 · 太傅：页面上下文与空档案出口

## 背景

r77 交付后立刻暴露出三个粗糙点，全部来自「用户真的会这么用」：

1. **指代没法落地**。用户在报告页问「这条什么意思」「这里为什么低」，太傅看不到用户在哪个页面，
   只能反问或泛泛回答。面板明明写着「当前：医案」，提示词里却没有这一行。
2. **空档案会留下孤儿消息**。没有记录的用户发问，服务端按设计不落库、只回中文说明；
   但前端先把问句乐观插进了列表 —— 于是界面上出现一条「有问无答」，刷新后凭空消失。
3. **空档案只说「先去补」，不给路**。用户被告诉「先上传简历或做一次测评」，
   但面板里没有可点的入口，得自己关掉浮窗去找。

## 目标

> 让「这条 / 这里」有指代，让「没有记录」有出路，让界面上不留下刷新即消失的假消息。

## 范围

| 改动 | 说明 |
| --- | --- |
| 页面上下文 | 前端传 `page`（pathname），服务端按**闭集白名单**归一后写进提示词；页面不是依据，不进引用白名单 |
| 空档案回滚 | 回答为空时收回乐观问句、把内容放回输入框，只留中文说明 |
| 空档案出口 | 读数 0 段时给「去上传简历 / 先做几道练习 / 去看诊断报告」三个可点入口 |

明确不做：不把页面内容抓成材料、不做面包屑式多页上下文、不做「引用到你正在看的这一条」的锚点（需要报告页支持锚点定位，另立需求）。

## 验收标准

- [ ] **AC-1 指代可解**：前端每次提问都带上当前 pathname；服务端只认闭集里的页面，写进提示词 `【当前页面】`，未识别时写「未识别」而不是猜。
- [ ] **AC-2 页面不污染引用**：页面上下文**不进**引用白名单——模型不能引用「你正在看的页面」当依据；越界引用仍按 r77 规则丢弃计数。
- [ ] **AC-3 不可注入**：`page` 只按闭集映射成固定文案；任意路径（含 `../` 穿越、未登记页、空串）一律不认，不会把用户输入拼进提示词。
- [ ] **AC-4 空档案不留假消息**：回答为空时列表回到发送前的状态，输入框恢复原问句，notice 照常显示；刷新前后一致。
- [ ] **AC-5 空档案有出路**：`materials_used = 0` 时出现三个站内入口，点击可跳转。
- [ ] **AC-6 不回归**：r77 的引用白名单、两步清空、收起态零请求、拖拽与位置记忆全部不变；两端测试与构建全绿。
