# r46 · 模拟笔试子方向聚焦可用性修复

日期：2026-11-09｜类型：缺陷修复 + 逻辑变更（前端文案 + 后端组卷）

## 1. 需求来源

r44 给模拟笔试加了「方向聚焦 / 二级方向」筛选，但筛选是**硬过滤**：组卷要先凑够 10 题（`rules.MIN_EXAM_QUESTIONS`），
子方向池与方向池共用同一套结构闸门。实测后果三类：

1. **必错入口**：12 个子方向题量 < 10（如图 1、链表 2、复杂度 4、排序 9、CI-CD 4/5、消息队列 7、索引 9、事务与 ACID 9），
   3 个子方向题库里 0 题（计算机基础·组成原理、SQL·NoSQL、研发工程实践·架构设计）。用户点了下拉里的选项就直接 400
   「题库不足，暂无法出卷」。
2. **聚焦永远落到 L5**：L1–L4 都要求方向覆盖 ≥2，单方向候选池永远不满足 → 任何方向/子方向筛选的卷都掉到 L5，
   熟练度过滤在聚焦场景下实际失效。
3. **毫无提示**：前端下拉列的是闭集全量，没有一个入口能看出「这个子方向没题」。

## 2. 方案与取舍

用户批准的方案：**方向 / 难度仍是硬过滤，子方向改为「聚焦优先、不足补位」**。

### 后端（`services/assessment/exam_selector.py`）

- 候选池拆成两层：`scope`（方向/难度硬过滤后的宽池）与 `focus`（再叠加子方向的窄池）。
- 参数归一：方向/子方向 strip 后为空 → 当未指定；子方向不在闭集内 → 当未指定（脏参数不再让卷面变空）。
  `scope` 为空（方向/难度本身没题）才返回 `None`（调用方 400）。
- 6 层阶梯本身**零改动**，抽出 `run_ladder(pool_ids)` 在两个池上复用：
  先跑 `focus`，成卷则 `sub_direction_backfill = 0`；凑不出才跑 `scope` 并用同方向其余题补位，
  补位数 = 卷中 `sub_direction != 所选子方向` 的题数。
- **方向覆盖基线联锁**：方向聚焦时（指定 direction 或子方向）`require_directions` 两档从 2/1/0 降为 1/1/0，
  L1–L4 的方向要求因此可达 —— 聚焦场景重新吃得到熟练度过滤，而不是永远落到 L5。
  不传任何筛选时 `scope` = 全库、基线 = 2，与改造前逐字节等价。

### 契约（`schemas.py` + `types.ts` 双侧同步）

`ExamRun` / `Paper` 新增两字段（默认空串 / 0，旧客户端与旧卷读侧安全）：

| 字段 | 语义 |
|---|---|
| `sub_direction` | 实际生效的子方向（闭集内取值；未指定或脏参数时 `""` = 未聚焦） |
| `sub_direction_backfill` | 本卷中**不属于所选子方向**、因题量不足而补齐的题数（0 = 全部命中） |

payload 同步落这两个键；`exam.py` 的 `create_run()` 装配与响应两侧都补上。

### 前端（`lib/examNotice.ts` + `pages/ExamPage.tsx`）

新增纯函数 `subDirectionNotice(subDirection, backfill, total)`（与 `filteredNotice` 同一静默口径，前端不重算、不改写）：

- 未选子方向 / `sub_direction` 为空 → `null`（不挂节点）；
- `backfill <= 0` / 缺失 / `NaN` / `±Infinity` → `null`（聚焦生效，无需说明）；
- `backfill >= 卷题数` → 「『X』暂无可用题目，本卷已改按同方向出题」；
- 部分补位 → 「『X』题目不足以单独成卷，已补充 N 道同方向题」。

渲染两处：作答中视图独立一行（`<Chip label="方向聚焦" />` + 文案），结果面板 join 进同一行透明度说明。

## 3. 验证结果

- 后端 `python -m pytest -q` 全绿；新增 5 个用例（宽池零补位 / 薄池补位计数 / 零题子方向退化为同方向宽池 /
  子方向聚焦不再落 L5 / 方向聚焦从 L1 起生效）。
- 后端 `python -m ruff check app tests` 通过。
- 前端 `npm run typecheck` / `npm run lint` / `npm test`（237 用例，含 6 个新增 `subDirectionNotice` 用例）/ `npm run build` 全通过。
- 契约门禁 `test_engineering_gates.py::test_contract_mirror_filtered_count` 的 `ExamRun` 字段白名单同步补两项。

## 4. 已知限制

- **方向 + 难度组合仍可能 400**：难度是硬过滤，某方向某档题量不足 10 时仍走「题库不足」。这是刻意保留的（难度是用户明确选择，
  静默放宽会失真），后续若需要再评估「难度不足补位」的独立需求。
- **补位是「同方向其余题」**：补位题的难度 / 相关度排序仍走 `rank_pool()`，不受子方向影响；文案只披露数量，不承诺具体分布。
- 子方向题量分布是静态事实（题库 1088 题），未新增统计接口；下拉闭集未改动。
