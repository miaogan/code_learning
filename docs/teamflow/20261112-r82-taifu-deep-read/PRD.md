# r82 · 太傅：按需深读 + 页面就地发问

## 背景

r77–r81 把太傅的「问 / 引 / 记」三条主干补齐了，但它读到的材料始终只有一层：
`brief.build_sections()` 把画像、最近一份报告、近 5 场测评、练习统计、学习进度
压成 2–3KB 的**摘要投影**。这套设计的收益是稳（有上限、可引用、不烧上下文），
代价是太傅只能回答「我弱在哪、先补哪、方向对不对」，回答不了「**这一条**怎么补」。

而「这一条」恰恰是用户最想问的那一刻：

- 站在医案第 3 条薄弱分组上，看到「事件循环 · 错误率 75%」，想问「这组我到底缺什么」；
- 在演武错题本展开一道题，看到解析没看懂，想问「这题为什么错」；
- 在简历改进要点看到「原句：负责接口开发」，想问「这句该怎么写」。

这三处都在站内、都有真值，只是没进提示词。同时现有的引用是**单向**的：
太傅能指到报告某一行（r79 的 `#weakness-N`），但页面没法把「我在看这一行」告诉太傅。

## 目标

> 用户在页面上看到某一条时，能就地叫太傅过来；太傅真的读到这一条的明细，
> 并且这条明细同样可核对（能引用回它所在的页面）。

## 范围

| 改动 | 说明 |
| --- | --- |
| `focus` 契约 | 请求新增可选 `focus`：闭集三类 —— 薄弱分组（报告第 N 组）、错题（题 id）、简历要点（逐字原句） |
| 取料层 | 新 `services/taifu/deep_read.py`：校验 focus → 读明细 → 投影成与档案段同形的一段（含 href） |
| 白名单 | 明细段**进**白名单；只进本次真读到的那一条。未读到的页面仍不可引用 |
| 提示词 | 新增 `【重点明细】` 段 + 系统规则一条：明细与档案同为依据，优先用它回答「这条 / 这题 / 这段」 |
| 契约可见性 | 响应新增 `detail`（kind / label / href，没读到时为 null），界面显示「已读取：薄弱明细 · 事件循环」 |
| 页面入口 | 医案薄弱组、医案简历改进要点、演武错题本三处「问太傅」按钮；跨组件唤起走 `lib/taifuBridge.ts` |
| 浮窗 | 焦点可见（「正在问：薄弱 · 事件循环 ×」）、可取消、路由变化清空；回答支持轻量列表与复制 |
| 富文本 | 回答按 `-` / `1.` / `**粗体**` 轻渲染（原先 `- ` 会原样裸露），每条回答可一键复制 |

### 明确不做

- **不做自动深读**：不根据问句猜「大概在问哪一段」。focus 只能来自页面的显式点击，
  否则取哪一段、取多少都不可控，成本与白名单都会失去边界。
- **不做二次模型调用**：不先让模型判意图再取料（那会把单次问答变成两次、等待翻倍）。
- **不做教程正文 / 历史报告对比的深读**：教程内容在 `frontend/src/content/tutorials/*.ts`，
  服务端读不到，接进来要先搬内容（独立一轮）；报告对比要另开一条查询口径。
- **不改「参谋不是执行器」**：仍只写太傅自己的三张表，不改画像、不改计划、不投递。
- **不做焦点组合**：一次只读一条明细。

## 三类明细的口径

| kind | focus 字段 | 校验（不通过即视同没传） | 明细内容 | href |
| --- | --- | --- | --- | --- |
| `weakness` | `index`（1 起） | 报告存在、`weakness_map` 是数组、`1 ≤ index ≤ len`、该组有 samples | 分组信息 + 每题题面 / 正确答案 / 你的结果 / 解析（题面与解析各截断） | `/report#weakness-N` |
| `attempt` | `question_id` | 题目存在，且**本账号有该题的作答记录** | 题面全文、选项、正确答案、最近一次作答结果与时间、解析 | `/practice` |
| `resume` | `anchor`（逐字原句） | 简历正文存在，且 `anchor` 能在正文里逐字找到 | 该条的位置与问题 + 原句 + 正文前后文窗口 | `/polish` |

预算：明细段最多 8 行、每行 160 字（比档案段的 6 行 / 120 字略宽，因为要放题面与解析），
整体约 1–1.5KB。

## 验收标准

- [ ] **AC-1 焦点是闭集**：`kind` 只认三个值；`focus` 缺省、空对象、kind 非法、字段越界一律等同「没传」，
      走原有摘要问答，不报错、不白屏。
- [ ] **AC-2 三类明细内容正确**：题目/解析/作答结果来自库里的真值；简历明细的上下文窗口必须真的包含原句。
- [ ] **AC-3 有预算**：明细段行数 ≤ 8、单行 ≤ 160 字，超长截断带省略号。
- [ ] **AC-4 白名单只扩到本次读到的**：明细的 href 可被引用；没有明细时 `/polish` 等页面不可被引用（丢弃并计入 `dropped_citations`）。
- [ ] **AC-5 无 focus 零变化**：r77–r81 的摘要、页面上下文、锚点、摘要/长期记忆、空档案出口行为与文案全部不变。
- [ ] **AC-6 三处入口可用**：报告薄弱组、报告简历要点、错题本展开行各能唤起浮窗，且带对焦点。
- [ ] **AC-7 焦点透明**：面板显示当前焦点与「已取消」入口；切换路由后焦点清空，不会把上一页的焦点带到下一页。
- [ ] **AC-8 回答可读**：列表与编号渲染为真实列表，粗体渲染为强调；每条回答可复制，复制内容是纯文本原文。
- [ ] **AC-9 不回归**：后端 pytest 全绿、前端 typecheck / lint / test / build 全绿。

## 已知限制

- `question_attempts` **只存对错、不存用户选了什么**（DDL 无该列）。所以错题明细只能说
  「你答错了 / 正确答案是 B」，说不出「你选了 C」。要补这一层得先改作答契约，不在本轮。
- 简历明细是**正文窗口**（原句前后各 180 字），不是完整段落；段落边界只有 `ResumePointer.section` 这一层粒度。
- 一次只读一条明细：用户在报告里同时问两个薄弱组，只会读到点击的那一条。
- 明细质量取决于题目解析字段（`questions.explanation`）本身写得如何：解析为空时明细只剩题面与答案。
- 焦点是前端传的，服务端只做闭集与归属校验（是不是你的报告、你的作答、你的简历正文），
  不保证用户「真的在看那一页」——但这只影响提示词的相关性，不影响白名单，因为明细本身仍是服务端真值。
