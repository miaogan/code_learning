# r95 · 学习计划按日历推进

## 1. 背景

「7 天学习计划」（r41 起）此前只有 **Day 1–7 的相对序号**：

- 计划没有起始日，Day 1 是哪天、今天该做哪天，界面答不出来；
- 打卡状态能跨设备（r61），但「今天」这个概念只存在于用户脑子里；
- 7 天窗口走完后没有任何交代 —— 计划永远停在 Day 7，落后多少、要不要顺延都没人管。

结果：计划看起来像一张静态清单，而不是「今天该做什么」的日程。

## 2. 目标

1. 计划有一个**明确的起始日**：用户点「今天开始」，Day 1 = 当天；
2. 打开报告页就能看到**今天是第几天**，以及前面有没有落下；
3. 落了能**一键顺延**（把第一个没做完的那天挪到今天），过期能**从今天重新排**；
4. 起始日与打卡走同一条同步路径：**换设备登录同一账号，今天还是同一天**；
5. 口径不变：打卡只记「做完」，不计入熟练度与成绩，不产生任何成绩数据。

## 3. 不做

- 不做提醒 / 推送 / 日历订阅（无通知基础设施，且与「本地优先」形态冲突）；
- 不改排程算法（权重、装箱、通用补位一律不动）——本轮只加**时间锚点**；
- 不做「按天自动跳过未完成」——顺延必须由用户点，静默挪动会让进度失真；
- 不为「过期」新造一份计划快照：顺延只是改起始日，打卡按 `task_id` 保留。

## 4. 验收口径

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-1 | 首次打开报告页（无起始日） | 显示「计划还没开始计时」+「今天开始」按钮；不标今天、不算落后 |
| AC-2 | 点「今天开始」 | 立刻标出「Day 1 今天」，起始日随打卡一起上推服务端 |
| AC-3 | 隔一天再打开 | 标出「今天是第 2 天」；Day 1 若没做完显示「前面还有 1 天没做完」+「顺延到今天」 |
| AC-4 | 点「顺延到今天」 | 第一个没做完的那天变成今天，已完成的天与打卡不丢 |
| AC-5 | 7 天窗口走完 | 不再假装今天是第 7 天：显示「7 天已经过完，还剩 N 天没做完」+「从今天重新排」 |
| AC-6 | 换设备 / 清缓存后登录 | 今天仍是同一天（起始日来自账号，本地只做缓存） |
| AC-7 | 脏数据（`2026-02-31` / `2026/11/12` / 未来日期） | 服务端静默落空串（不 422）；前端按未开始 / 第 1 天处理，不崩不跳 |
| AC-8 | 打卡与成绩口径 | 与 r41 完全一致：不计熟练度、不进报告分数、不进成长时间线 |
