# PRD · r42 画像任务化 + 断连恢复 与 HEIC 兜底

> 任务夹：`docs/teamflow/20261108-r42-task-recovery-heic/`
> 上游：r30（画像异步任务）、r32（失败可见性）、r33（24h 失败提示窗口）、r34（专用超时 + 重试）、r41（图片简历入口）。
> 原则：**兼容不推翻**；旧同步契约零改动；错误码闭集不新增。

---

## 1. 问题

| 场景 | 现状 | 后果 |
|---|---|---|
| 画像生成 200s 级，前端轮询 | r30 起已是服务端任务，但恢复锚点只在服务端 `latest` | 同一台设备上「我这次上传」与被清理 / 换设备后的任务无法区分，回到页面可能空白 |
| 图片识别（1–3 张视觉抽取） | r41 是**同步长请求** | 手机切 App / 锁屏 / 地铁断网即断，用户不知道任务是否还在 |
| 重复提交 | r30 每次受理都新建 running 行 | 连点 / 重试会产生多条重复任务 |
| 卡死任务 | r32 读路径惰性清扫，阈值 10 分钟 | 统一 AI 超时 600s + 重试一次，合法耗时可到 20 分钟 → **误判合法任务** |
| 断网 | 轮询 catch 后静默重试 | 一直转圈无任何提示，看起来像白屏 |
| HEIC | 前端 canvas 解码失败给笼统「图片打不开」；后端 sniff 判 `UNSUPPORTED_TYPE` 通用文案 | iPhone 用户不知道该怎么办 |

---

## 2. 目标与范围

**做**
1. 图片识别链路异步化：`POST /api/resumes/images/async` 受理即返回 `job_id`，轮询取结果，终态落库。
2. 幂等与并发：同一简历（画像）/ 同一批图片（识别）在途时复用同一任务；部分唯一索引兜并发。
3. 卡死治理：任务体硬 deadline + 读路径惰性清扫 + 图片任务逐页心跳。
4. 前端恢复：本地上传会话（按账号隔离、24h 失效）优先，服务端 `latest` 兜底；三态连续。
5. 断网提示：中文、可重试、不白屏。
6. HEIC：前端按真实字节提前拦截；后端识别后给专用文案与替代路径。

**不做**
- 不改 r30 同步 `POST /api/resumes/{id}/profile`、r41 同步 `POST /api/resumes/images` 契约。
- 不引入第三方 OCR / 服务端图片转码（HEIC 走「用户改相机格式 / 导出 JPG」路径）。
- 不做跨设备计划的持久化（属 r41 已知边界）。
- 不为轮询加 WebSocket / SSE：2s 短轮询在弱网下更稳，且无需长连接治理。

---

## 3. 验收标准

- **AC-1** 图片识别提交立即返回 `job_id`（<1s），页面进入「识别中」；离开 / 刷新 / 锁屏后回来自动接上。
- **AC-2** 同一批图片字节在途重复提交，返回同一 `job_id`；同一简历在途重复提交画像任务同理。
- **AC-3** running 行不会永远进行中：任务体超时落 `failed` + 中文；进程中断的行读一次即被清扫。
- **AC-4** 回到上传页三态连续：识别中 / 生成中 / 刚完成（30 分钟内）都能看到对应卡片；更早的完成回落到「已有画像」。
- **AC-5** 断网时出现中文提示（不白屏），恢复网络后轮询继续，任务不受影响。
- **AC-6** 选择 HEIC 时给出「设置 → 相机 → 格式 → 兼容性最佳 / 导出 JPG」的明确路径；后端同样识别并给专用文案，错误码仍是闭集里的 `UNSUPPORTED_TYPE`。
- **AC-7** 旧同步端点行为不变（既有调用方与测试无需改动）。
- **AC-8** 契约两侧同步、snake_case、错误 envelope 不变；窄屏 360–430 可用。

## 4. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 图片识别是否异步 | **是**（新增 async 端点，旧同步保留） | 1–3 张视觉抽取 10s–数分钟，属长请求 |
| 幂等键 | 画像 `(user_id, document_id)`；图片 `(user_id, sha256(字节))`，都只约束 running | 终态可重跑；历史任务照常可查 |
| 陈旧阈值 | 画像 30 分钟；图片按「无进展」10 分钟（逐页心跳） | 与统一 AI 超时 600s × 重试一致，不误杀合法任务 |
| 硬 deadline | 画像 25 分钟；图片 `3×600s + 300s` | 兜住「AI 客户端自身超时没生效」的挂死 |
| 前端恢复锚点 | 本地会话优先 + 服务端 latest 兜底 | 本地能区分「我这次」，服务端能跨设备 |
| 完成态回放 | 30 分钟窗口 | 连续但不长期霸占上传页 |
| 失败提示 | 维持 r33 的 24h 窗口 | 旧失败不长期打扰 |
| HEIC | 前端 + 后端双重字节识别，复用 `UNSUPPORTED_TYPE` | 不加码、不静默降级、文案可执行 |

---

## 5. 风险与边界

- 图片字节在任务运行期间留在内存（与 r41 同口径，不落盘）；3 张 × 10MB 上限已知。
- 服务进程重启会中断进行中的任务：行会被清扫为 `failed`，用户需重试（不承诺断点续跑）。
- 本地会话可被用户清缓存 / 换浏览器清掉：服务端 `latest` 兜底仅覆盖 running。
- iOS Safari 的 HEIC 转码行为未在真机实测（见 QA-REPORT §HEIC）。
