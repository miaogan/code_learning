# r79 · 太傅：引用指到报告里的具体那一条

## 背景

r77 给太傅接了真实问答，r78 让它知道用户在哪个页面。但引用仍然只到**页级**：

- 太傅说「第 3 条最该补」，引用是 `/report`。用户点进去，看到 20 条薄弱分组，
  得自己从上往下数第 3 条是哪一条 —— 而表格默认还折叠到 8 条。
- 更糟的是「第 9 条」这种情况：点进去根本没有第 9 行（在折叠区），
  用户得到的是「点了没反应 / 页面里找不到」。

也就是说 r78 的已知限制第 3 条（「引用仍到页级」）不是「少一个便利」，
而是「引用与回答说的不是同一件事」：回答精确到行，跳转模糊到页。

## 目标

> 太傅说到哪一条，点进去就停在哪一条——哪怕它在折叠区。

## 范围

| 改动 | 说明 |
| --- | --- |
| 段内锚点 | 薄弱分组段带上 `anchors`（`/report#weakness-N`），进**引用白名单**（段级 href 仍然有效） |
| 行内标注 | 摘要里每条薄弱行的末尾写 `→ /report#weakness-N`，让模型有东西可以逐字抄 |
| 落点定位 | 报告页读 `#weakness-N`：在折叠区就先展开，再 `scrollIntoView`，并给该行高亮 |
| 收起时机 | 浮窗的「路由变化即收起」补上 `hash`，否则同页锚点跳转后面板不会收 |

明确不做：不把锚点做成双向（用户在报告页点某行反查太傅说过什么）、不给锚点编号做稳定 ID
（`weakness-N` 是表格行号，报告重新生成后意义会变，由下一次报告整体替换）、不做 `#practice` 等其他页的锚点。

## 验收标准

- [ ] **AC-1 引用能落到行**：摘要的薄弱分组段返回 `anchors`，形如 `/report#weakness-1`，`N` 与报告页表格行号一致（1 起）。
- [ ] **AC-2 只白名单内的锚点有效**：`anchors` 只覆盖摘要里真写出来的分组（前 `MAX_WEAK` 组）。越界锚点（如 `#weakness-9` 而摘要只写 5 组）与伪造锚点（`/report#evil`）一律丢弃并计入 `dropped_citations`。
- [ ] **AC-3 段级引用不回归**：`/report` 本身仍然合法；同一 URL 同时出现在段与锚点时保留段标签（更短、更稳）。
- [ ] **AC-4 跨折叠也能看见**：目标行落在折叠区时自动展开到全量，再滚动到视口中央，行完整可见。
- [ ] **AC-5 用户认得出是哪条**：被引用的行有淡底 + 左侧竖条高亮；站内跳转与直接粘贴 URL 两条路径都要高亮。
- [ ] **AC-6 不回归**：r77/r78 的引用白名单、两步清空、空档案回滚与出口、拖拽与位置记忆全部不变；两端测试、typecheck、lint、build 全绿。

## 与既有约束的关系

- 太傅仍是**只读参谋**：本轮只多给模型一个「可以引用的 href」，写入面零变化。
- 白名单语义不变：仍然是「这次真读到了什么」的投影 —— 锚点也是服务端自己算出来的，客户端无法注入。
- 报告页仍是**纯投影**：不新增请求，锚点只影响「展开哪一行、滚到哪一行」，不改变任何数据。
