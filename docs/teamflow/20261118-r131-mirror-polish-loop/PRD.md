# r131：镜试缺项回灌修文（含成稿存为新简历版本）

- 日期：2026-11-18
- 发起：用户提出「镜试可以和修文联动——缺失信息引导用户编写并回灌到简历优化」
- 决策（用户确认）：回灌做到「成稿可一键存为简历新版本」全量；入口做双向（镜试卡跳转 + 修文页内置面板）。

## 1. 背景与洞察

两个模块的哲学天然互补：

| 模块 | 既有机制 | 边界 |
|---|---|---|
| 镜试（r125） | 复盘卡 `missing_info`（≤4 条 / 卡）：AI 只说缺什么、为什么影响说服力 | AI **不代填**，等用户自己补 |
| 修文（r3） | AI 润色建议 + 反幻觉门禁（新数字降级〈待补充〉、新专名整条丢弃） | 拦的是 **AI 发明**的事实；用户亲口提供的事实是合法新事实 |

联动 = 把「缺什么」（镜试）与「怎么写进简历」（修文）接起来，且不破坏任一侧的「不虚构」底线。

## 2. 交付范围

### 2.1 双向入口

- **镜试 → 修文**：`MirrorPage` 缺失信息每条加「去修文补写 →」（`Link` + `state.mirrorMissing`）。
- **修文内置面板**：`PolishPage` 顶部「镜试缺项补写」卡片——复用现有 `GET /api/mirror/cards`（零新契约）拉最近 10 条复盘，`collectMissingFacts` 拍平 + 按整条文本去重；每条可展开编写框（正文 ≤500 字 + 归属部分可空）；已确认内容以 chip 展示、可移除（≤6 条）。
- 跳转定位：`mirrorMissingFromState` 只认字符串；缺项列表到位后自动展开对应编写框（只应用一次）。

### 2.2 回灌：user_facts 织入润色

- 契约：`PolishRequest.user_facts: list[PolishUserFact]`（text 2–500 字，section 可空，≤6 条）；`schemas.py` 与 `types.ts` 同步。
- 提示词（唯一入口 `resume_polish.py`）：新「候选人补充的事实」小节 + 系统提示词第 3 条补例外条款——user_facts 视为真实、鼓励织入，除此之外仍不得新增任何事实。空列表时提示词与旧路径逐字节一致（测试固化）。
- 反幻觉精确放行：`validate_suggestions(extra_text=…)`——user_facts 原文逐字出现的**数字**进白名单（不降级）、**专名**进 haystack（不丢弃）；AI 自己发明的内容照拦。注意门禁是 **token 级**：facts 里有「8000」则任何「8000」都放行（与既有正文白名单同语义）。

### 2.3 成稿存为简历新版本

- 新端点 `POST /api/resumes/{id}/polish/save-version`：body `{markdown(50–100k 字), file_name?}`；来源文档按账号隔离（跨账号 404）；成稿 strip 后入库为新 `documents` 行（`mime=text/markdown` → 校勘页 source_type=txt；`file_name` 缺省 `修文成稿-YYYYMMDD-HHMM.md`；sections=1）。
- **时间线不在此插**：画像任务成功路径会按新 document_id 写「简历画像已更新」（`timeline.py` 既有机制）。
- **画像衔接**：前端保存成功后立即调既有 `generateProfileAsync(new resume_id)`；触发失败不回滚版本，横幅给手动路径（校勘页生成）。画像完成前新版本处于「无画像」态——与手动上传后的行为一致。
- 前端：成稿区新增「存为简历新版本」（`stale` 时禁用并提示先重新生成——保「成稿单源」不破）；成功横幅带校勘页链接。

## 3. 明确不做 / 未决

- 存新版本**不自动采纳全部建议**：成稿内容 = 用户在修文页已确认的 `/polish/full` markdown，服务端零再加工（AC-11 单源不变）。
- 补写内容**不落库**：与修文 `polish_id` 缓存同生命周期（进程内）；跨会话保留 user_facts 留待有真实需求再做。
- 镜试缺项与修文〈待补充〉占位的**自动配对**（哪条建议的哪个占位对应哪条缺项）是启发式难题，本轮不做；AI 织入靠提示词自由完成。
- 「8000」token 级放行的粗粒度是接受成本：宁可放行用户给过的数字，不可拦掉用户亲口的事实。
