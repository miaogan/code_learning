# DESIGN · r6 · 题库多维标签 + 熟练度过滤

**定位一句话**：本轮 90% 工作量在**数据层 + 服务端选池算法**，界面可见增量**只有一个信息行**（AC-12，P1）。因此本设计的主体不是新画页面，而是把「这一行长在哪、用什么既有类、多宽多高、什么时候不出现、什么绝不能做」写死到可直接实现，并为其余 AC 显式声明「无 UI 面」，防止下游在界面上造证据。

## 0. 观感规格（先读本节，实现细节都在这里）

### 0.1 基调（一句可执行）

**「卷子变聪明了，但界面不多长一块东西」**：用户感知到的全部视觉变化，是卷面顶部多了一行**带类别标签的定量事实**——`[熟练过滤]` + 「本次已过滤 N 道你已熟练掌握的题」，其余像素与 r1–r5 逐像素一致。形制沿用产品深色扁平面：**1 强调色 + 3 语义色**，靠 1px 边框与字号层级分层；信息行**不加容器边框、不加底色块、不加图标、不加渐变发光、不加入场动画**——它要像「卷面自身的说明」而不是「弹出来的提示」。

- `base.css`：**不改**（零新增类，`test_engineering_gates.py` 的「无裸色值」断言连 CSS 注释里的色值字面量都算）。

| `.sc-chip` | 高 `--chip-h` 24 / `--radius-4` / 1px `--border-subtle` / `--overlay-06` 底 / 12-16 500 / `--text-secondary` | 行首类别标签 |

### 0.4 动效 · 加载 / 空 / 错误

- **入场：无。** 信息行随卷面切态一次性渲染（React 条件挂载），不加 opacity/位移/stagger——它描述「这份卷是怎么组出来的」，是**卷面事实**而非一次性通知；做成动画会暗示「刚刚发生了一件事」。
  - 若将来产品坚持要动：只允许 `opacity 0→1`、时长 `--base`(180ms)、缓动 `--ease`，并在 `@media (prefers-reduced-motion: reduce)` 下 `animation: none`（与 r3 §0.4 同口径）。本轮不写。
- **加载（`creating`）**：沿用 `PhaseLoader`（既有三段文案 + 计时 + 「取消」）。**不允许**新增「已排除 N 道」这类实时进度条——服务端是一次返回，给不出真实进度，假进度违反诚实原则。
- **空（`empty` 无画像 / `error` 题库空或损坏）**：沿用既有 `EmptyState` / `InlineError`；题库表空/损坏走既有中文 `VALIDATION_ERROR`（AC-13），**不新增白屏、不新增错误组件、不抛栈**。
- **错误（L6 仍不足）**：沿用出卷失败路径——idle 卡内 `InlineError` + 既有文案「题库不足，暂无法出卷，请稍后重试」+「重新出卷」按钮。**「因过滤」的 400 本轮必须为零**，因此界面上不该出现新的失败面。
- **提交失败**：沿用 r1 既有「失败不清空作答、原地重试」语义，本轮不动。

### 0.5 几何自洽（逐条核算；改数必重算）

1. **行高**：`.sc-meta-line` 为 `align-items: center`，单行高度 = max(`--chip-h` 24, `--lh-meta` 16) = **24px**。
2. **390px 可用宽**：`390 − 2 × --sp-6(24) = 342px`（`.sc-page` padding 在 ≤640 断点未变，仍是 24）。
3. **chip `[熟练过滤]` 宽**：4 全角 × `--fs-meta`(12) = 48 + 左右 `--sp-2`(8)×2 = 16 + 边框 1×2 = 2 → **66px**。
4. **文本可用宽**：342 − 66 − `gap` 8 = **268px**。
5. **最长实例**（N 最多 2 位，全库 80）：「本次已过滤 80 道你已熟练掌握的题」= 14 全角字 ×12 = 168 + 两位数字 ≈13 + 空格 ≈7 → **≈188px ≤ 268**，余量 **80px** → 390px 下**恒单行**、不换行、无横向滚动。**320px 下**可用 320−48−74 = **198 ≥ 188**，仍单行。
6. **纵向节奏**：行上 24 = `.sc-page-header { margin-bottom: --sp-6 }`；行下 16 = `.sc-actions { margin-top: --sp-4 }`；信息行自身 `margin: 0`。**禁止**再给它补 margin/padding，否则与既有 24/16 叠加，首屏节奏断掉。
7. **封闭形状核算**：本轮**不新增任何内含文字的封闭形状**（无环、无 MM:SS 徽章、无 HUD 槽），故不涉及「半径 − 描边 ≥ 文字半对角」这类约束；r1 §0.7 的 `--ring-lg(64)/--ring-md(56)` 核算不变。
8. **兜底情形**：若 N 意外出现 3 位数（不会发生，全库 80），`.sc-meta-line` 的 `flex-wrap: wrap` 会让文本落到第二行（行高 24 + gap 8 + 16 = 48），**仍无横向滚动**。

### 0.6 本轮新增禁止项（anti-patterns · r6）

- **过滤静默**（PRD 反面目标 1）：`filtered_count > 0` 时页面上必须能读到这一行；不许把它塞进 hover tooltip、折叠区、`console.log` 或「详情」入口。
- **为提示新增 CSS 类 / 新色值 / 新 token**（AC-12 明令）：尤其不许给信息行加渐变、发光、danger 色或新的 tint 变量。
- **把信息行做成可点**：点击无处可去（本轮不做题库/熟练度管理界面，PRD 非目标 1），可点会诱导用户寻找不存在的入口。
- **N=0 时渲染空字符串或占位**：会留下 24px 空白并制造「本次已过滤 0 道」这类误导性断言——条件是**不挂载节点**，不是隐藏。
- **弱化成「已过滤 N 题」**：丢掉「你已熟练掌握」就丢了归因（用户不知道是被过滤还是题库变小了），文案必须逐字包含 AC-12 的原句。
- **在提交后的结果面板里重复同一条**：提交态视觉焦点是 40px 总分与逐题解析，重复会把焦点拉走，且该事实在作答态已经看过。
- **把 `stage`（L1–L6）暴露到界面**：层号是 QA 凭 payload 断言的内部事实，用户读不懂 L4/L5/L6，暴露反而让「兜底」看起来像缺陷。
- **为「题库不足」新建错误态视觉**：仍走既有 `InlineError` + 既有中文文案。
- **给信息行加 `aria-live` 或入场动画**：它不是通知事件，是卷面构成；`aria-live` 会在每次切态时重复播报。
- **改动题卡/进度 chip/计时环的任何既有样式**：本轮零回归是 P0（AC-10）。

**JSX 契约（可直接照抄）**：


## 4. 交互规则补充（与 AC 强相关）

1. **一次性计算**：值来自出卷响应，作答过程不会变；不要在 `submitting`/提交成功后重算或清零（卷面构成是历史事实）。
2. **N=0 不挂载节点**（不是 `display:none`），因此不存在空行、空占位、空 aria 节点。
3. **提交态不重复**：`submitted` 分支不渲染该行（理由见 §0.6）。若产品/QA 要求提交态也可见，插入点改为 `submitted` 分支首行即可，视觉规格（§0.3/§0.5）不变——这是**已批准的等价替换**，不算设计变更。
4. **不做 toast**：一次性提示会与提交失败的 `InlineError` 抢层级，且 toast 会消失、用户回头找不到解释。
5. **重新出卷**：点「再出一套笔试」→ `creating` → 新 `run` 覆盖旧值 → 行随卷面重渲染；新旧卷之间**不做**数字变化的动画/计数器。
6. **兼容旧响应**：`filtered_count` 缺失、`null`、非数字 → 一律按 0，不渲染、不报错、不 `console.error`（r5 及更早的 fixture 必须继续通过）。
7. **无键盘影响**：不新增 tab stop、不新增快捷键；Tab 序列与 r5 完全一致。

## 5. 无障碍要点

- **语义**：`<p>` 段落 + 内部 `<span>`；不带 `role`、不带 `aria-live`（卷面事实随渲染一次呈现，不重复播报）。chip 是不可点的 `<span>`，不进 tab 序。
- **对比度**：正文 `--text-tertiary` 在 `--bg-canvas` 上 **≈5.6:1**、在 `--bg-surface` 上 **≈5.1:1**，均 ≥ 4.5:1（AA 正文）；chip 文字 `--text-secondary` 在 `--overlay-06` 叠底上 **> 8:1**。
- **不靠颜色传达**：过滤这一事实由**文字**承载（chip 只是类别标签）；色盲/高对比模式下语义不丢。
- **缩放**：`>=200%` 文本缩放下 `.sc-meta-line` 折行而非溢出（`flex-wrap: wrap`）；390px 无横向滚动（§0.5-5）。
- **数字可读**：N 为整数、与中文同句，读屏顺序为「熟练过滤 本次已过滤 N 道你已熟练掌握的题」——顺序正确，不拆分。

## 7. 对下游（技术方案 / 实现）的契约输入

1. `ExamRun.filtered_count: int`（默认 0，旧响应对齐），前端读侧 `?? 0`；类型必填或可选由技术方案定，但**读侧默认 0** 不可省。
2. 前端只改 `ExamPage.tsx` + `api/types.ts` 两个文件；`base.css` / `tokens.css` 必须**零 diff**（评审时直接看这两个文件的 diff）。
3. 信息行插入点为 `running | submitting` fragment 首子节点；不新建组件文件、不新增 CSS 类。
4. 「因过滤的 400」必须为零（AC-8），因此前端**不得**新增任何「题库变小/被过滤」类的错误文案分支。
5. 运维事实不在界面：`stage`、各层回流明细只进 payload；如后续需要「已掌握/待突破」视图，单独立需求（PRD 非目标 1 的后续入口）。
