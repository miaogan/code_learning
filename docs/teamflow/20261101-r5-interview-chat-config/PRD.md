# PRD · 模拟面试对话化与面试配置项（r5）

## 1. 背景与目标

当前模拟面试（`frontend/src/pages/InterviewPage.tsx` + `backend/app/services/interview.py`）是**一次性出题 + 逐题单屏**：`create_run` 一次让模型产出 ≥8 道题全量返回，前端每次只显示一题、`score_answer` 单题回写。r1 当时即在假设区写下「面试交互形态：默认逐题单屏卡片；若你更想要连续对话式面试，评分粒度与页面结构都要改」——本轮就是那次改造。

**用户问题**：真实面试是**对话**：面试官会基于你的回答追问、澄清、给压力；而当前形态是「考试卷」，体验与求职口语训练脱节。同时**一场面试的口径完全没有输入口**：画像里的目标岗位与年限是唯一依据，用户无法表达「我这次要面北美大厂的高级岗」或「我应届想面初创全栈」——出题口径与实际投递目标错配。

**目标（可判定的完成态）**：
1. 用户开场后看到的是**对话**：面试官一条条说，回答后在气泡里立刻拿到分数与点评；面试官的下一条发言能看出是接着你的回答问的。
2. 开场前可填（也可整场跳过用画像默认）**目标岗位 / 工作经验 / 面试市场 / 公司规模**四项，且这四项**真的改变出题与追问口径**，不是摆设。
3. 每场面试的设定**随会话落库**，能在历史记录与诊断报告里回溯「本次面试设定」。
4. r1–r4 建立的证据链与门禁**一项不丢**：每题仍可 0–10 评分、题号可溯源、均分与报告不受破坏。

**已实测的当前基线**（本轮以此为回归下限）：

- `backend/`：`python -m pytest -q` → 118 passed（本轮实测确认）
- `frontend/`：`npm run typecheck` → 0 error；`npm run lint` → 0 error / 28 warning；`npm test` → 23 passed；`npm run build` → 通过
- 仓库无真实 AI Key（`backend/.env` 不存在，仅 `.env.example`）→ 「配置真实影响出题」的自动化证据只能用 fake client 捕获提示词，端到端冒烟需人工补测（见 §10 F1）。

## 3. 范围与非目标

## 5. 交互流程摘要

1. **前置三态**：无画像 → `EmptyState`（中文原因 + 「上传简历」主按钮）；加载中 → 步进文案；失败 → `InlineError`（中文 + 重试）。
2. **配置**：4 项预填（见 AC-1 映射）→「开始面试」；或「跳过，用画像默认」。开场后表单收敛为只读摘要条（本场设定可见）。
3. **开场**：一次 AI 调用产出「本场计划」（≥8 题、配比合规）+ 第 1 条面试官发言（气泡）；计划不合格 → 502 中文 + 可重试（不落库）。**此时用户只看到 1 条发言**。
4. **轮次**：候选人在粘性输入区作答 → 提交 → 服务端在同一轮内产出「本轮评分（0–10 + ≤120 字点评）+ 下一条面试官发言（追问或下一正题）」（≤15s）；气泡流内候选人气泡下方紧跟评分徽章与点评，面试官气泡显示新问题。
5. **追问**：面试官可对上一答追问 / 澄清 / 施压（新 `iq-N`、`parent_id` 指向父题、`kind` 继承父题），追问同样独立评分；默认总题 ≤12（8 正题 + ≤4 追问，见 §10 Q1）。
6. **结束**：计划耗尽（且无追问）→ 会话结束态（均分 / 答题数 / 「去看诊断报告」CTA），run 置 `completed`，时间线事件沿用现有落点。
7. **回溯**：历史页每条面试记录显示设定摘要；报告页顶部显示「本次面试设定」；任何时刻可用 `run_id` 重开会话（已完成 = 只读）。

**UI 设计要求**（交设计阶段，验收见 AC-17）：对话气泡流的左右区分与最大宽度、评分徽章 + 点评与候选人气泡的并置关系（点评不得漂浮到屏幕另一侧）、配置表单的开局前一屏形态与开场后摘要条、长会话自动滚动锚点（新气泡进入视口且评分同屏）、窄屏单列布局、结束态与进行中态的视觉区分。

## 6. 反面目标（anti-goals）

即使测试全绿、下面任一条发生，本需求也应被判为失败：

1. **「对话化」只是换皮**：开场后用户就拿到了全部 8 道题（响应里带着题目列表、或首屏铺开 8 张卡片），只是把卡片换成了聊天气泡样式——用户读到的仍是卷子，不是对话。
2. **答完看不到分，或刷新即清空**：评分 / 点评被折叠到「查看评分」或推到滚动区外，用户答完第一屏看不到自己几分；刷新或重进页面后气泡与分数消失，甚至同一题被再次计分——对话流最需要的「即时反馈 + 不丢上下文」两件事同时失效。
3. **配置是摆设**：同一画像、同一岗位下，选「初创 · 应届 · 北美」与完全跳过配置，发出的提示词与题面毫无差异；用户填了 4 项却换不来任何可感知的差别，等于虚假配置。
4. **临时值污染画像**：在面试里改的目标岗位 / 经验被写回画像，用户回到画像页发现 `target_role` 被永久改掉——一次面试偷偷改了长期资产。
5. **结构失守**：多轮增量生成把这一场做成「8 题全是技术题」或「5 道挑战题（>20%）」，报告里再也凑不出 3 条项目深挖证据——对话体验上去了，诊断证据链断了。

## 8. 依赖与风险

**依赖（既有实现，不得各自另写一份）**

- `services/ai.py`：`complete_model(timeout_s=...)` 与超时 → `AI_UNAVAILABLE` + 503 的统一映射（单轮预算的唯一入口）。
- `services/rules.py`：`MIN_INTERVIEW_QUESTIONS=8` / `MIN_TECHNICAL_QUESTIONS=5` / `MIN_PROJECT_QUESTIONS=3` / `MAX_CHALLENGE_RATIO=0.2`（阈值唯一出处）。
- `services/diagnosis.py`：读 `payload.questions[]` 的 `id` + `score` 组成「题号 + 得分」证据（payload 形状必须向后兼容）。
- `services/history.py`：面试均分口径 `score_of`（只统计已评分题；追问也进分母，**口径不改，避免两套算法**）。
- `services/timeline.py`：`record_run_event` 的 `(type, ref_id)` 幂等。
- `repository.py`：唯一 SQL 出口；`runs` 表（`id / kind / profile_id / payload / status / created_at`）已够用，**不需要新表**。

**风险**

1. **单轮 15s 预算 vs「评分 + 下一条发言」同轮产出**：上下文变长易超时。缓解：有界历史窗口 + 计划预生成（开局已定题面骨架），逐轮只做「评 + 改写/追问」；超时按 AC-10 整轮失败可重试，不出现「评分已出、下题悬空」的半成品态。
2. **计划质量不稳**：模型给的计划可能配比不合规 → 502 重试率上升。允许**整份重新生成**（不视为补题），但禁止插入/替换单题凑配额。
3. **追问改变均分语义**：追问独立评分后进均分分母，与历史趋势相比略有漂移——接受（口径单一优先，见上）。
4. **旧 run 兼容**：r1–r4 的历史面试 run 无 `settings` / `parent_id` / 计划，读取必须容错（缺字段 → `null` / `[]`），显示「未记录设定」。
5. **环境无真实 AI Key**：配置真实生效只能以 prompt 捕获断言 + 人工冒烟取证（§10 F1）。
6. **对话 UI 与无新依赖约束**：不加组件库、不做流式，长会话滚动锚点与窄屏只能手写 CSS —— 需要 DESIGN 先给几何与推导，避免返工。

## 10. 假设与待澄清

- **F1（事实 · 无真实 AI Key）** 当前仓库只有 `.env.example`、没有 `backend/.env`，因此「配置真的影响出题口径」无法端到端自动验证。按 AC-2 采用：fake client 捕获每轮提示词 + 纯映射函数单测作为自动化证据，端到端差异由 QA 人工配真实 Key 冒烟并登记。**若你坚持要求端到端自动验证**：需要一个可用 Key 的测试环境，且冒烟耗时与非确定性会进入每轮回归成本。
- **Q1（口味 · 追问与总轮次上限）** 需求要求「多轮 + 追问」，但没说一场能聊多少题。**推荐**：8 道正题 + 每场 ≤4 次追问，总题 ≤12，每题独立评分。**若你要严格 8 轮**：对话感会明显变弱，追问只能作为同题内的一次澄清（不计新题）；**若你要不限追问**：一场可能拉到 20 轮以上，时长与均分可比性都下降。
- **Q2（口味 · 北美市场的语言口径）** 「北美市场考英文表达」有两种落法：**推荐**题面中文、但要求在关键术语 / 项目亮点 / trade-off 上用英文表述（不整场英文，保住可读性与作答质量）；**若你要整场英文题面**：用户可能直接放弃作答，需要额外的「英文作答模式」开关与提示，且评分口径要重写。
- **Q3（口味 · 配置能否中途改）** 需求说「开局前可填」。**推荐**：开场后**锁定只读**，中途想改口径就重开一场（会话与配置一一对应，回溯干净）；**若允许中途改**：同一 run 内会出现前后两套口径，报告里的「本次面试设定」需要记录变更历史。
- **Q4（口味 · 配置入口形态）** **推荐**：开局前**一屏表单**（可直接跳过），开场后收敛为只读摘要条贴在会话顶部；**若你更想要**「页内常驻可折叠侧栏」：窄屏要付出额外的展开层级，且与「中途不可改」冲突。
- （事实类其余项已从仓库 / 状态索引确认并落进 AC：配额阈值取自 `rules.py`、payload 复用 `runs.payload` 不建表、旧 run 只读不迁移、单轮 15s 预算沿用 `SCORING_TIMEOUT_S=14`。）
