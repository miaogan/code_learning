# r80 · 太傅：长线程的早期上下文不丢

## 背景

r77 起太傅能读档案、能连续对话，r78 补了页面指代，r79 把引用落到具体一行。但对话本身有个越用越糟的结构性问题：

- 写进提示词的只有**最近 6 条**（3 轮）原文。第 4 轮开始，最早那轮就永久消失。
- 于是十几轮之后：用户早说过的背景（「我在外包，只有周末能学」）丢了，太傅会再问一遍；
  已经给过的结论（「先补部署与推理，再补缓存一致性」）也丢了，太傅会换一套说法重讲一遍。
- 用户感知到的不是「上下文有限」，而是「这助手记性差、说话反复」。

这是**窗口截断**问题，不是模型能力问题：档案部分是每次全量重读的，唯独对话会衰减。

## 目标

> 十几轮之后，太傅仍然记得开头说过什么 —— 且不因此多花一次模型调用。

## 方案选择

| 方案 | 否决 / 采纳理由 |
| --- | --- |
| 加大窗口（如 20 条原文） | 不解决衰减，只是把墙推远；提示词线性变长，成本与延迟都涨，且长文里关键结论更容易被稀释 |
| 单独调一次模型做摘要 | 每 N 轮多一次调用与一次失败面；太傅是前台交互，用户等不起第二次往返 |
| **让模型在回答的同一次输出里顺带回写摘要** | 采纳：零额外调用、零额外延迟；失败时自动退回现状（摘要为空 → 提示词与今天完全一样），不会更差 |
| 服务端确定性截断（把旧消息压短） | 只能压「问过什么」，压不出「建议过什么」，而这恰恰是最该留的部分 |

## 范围

| 改动 | 说明 |
| --- | --- |
| 模型输出 | JSON 增加 `memory` 字段（≤240 字，单行）；仅在窗口**真的溢出**时才要求模型填 |
| 线程记忆 | 新表 `taifu_threads`（一账号一行）存摘要；提示词新增 `【早期对话摘要】` 段 |
| 净化 | 压成单行、截断、占位词（「无」「N/A」）视为没给 —— **不拿空串覆盖旧记忆** |
| 边界 | 记忆**不进引用白名单**：它是模型自己写的话，不是站内记录；有冲突以档案为准 |
| 清空 | `DELETE /thread` 同时清记忆（否则「空对话」只是用户看不见，模型仍带着上一段） |

明确不做：不做跨线程的多话题记忆、不做「记忆条目」的结构化存储（仍是自由文本）、不在界面上展示摘要
（用户要看的是回答，不是太傅的记事本）、不做记忆的手动编辑。

## 验收标准

- [ ] **AC-1 溢出才压缩**：窗口装最近 6 条；只有当消息数 > 6（第 1 条真被挤出去）时才在提示词里要求模型回写摘要，短线程零额外输出。
- [ ] **AC-2 记忆进提示词**：非空记忆以 `【早期对话摘要】…` 出现在档案之后、当前页面之前；为空时写固定占位而不是留空段。
- [ ] **AC-3 记忆不是依据**：白名单仍只由档案段构成；模型若引用只出现在记忆里的 href → 丢弃并计入 `dropped_citations`。
- [ ] **AC-4 空值不覆盖**：模型回「无」「N/A」「（无）」或空白时，保留旧记忆原样（不能把有用的摘要洗掉）。
- [ ] **AC-5 先成功再写**：回答为空时既不写消息也不写记忆；记忆与对话同批提交。
- [ ] **AC-6 清空即清空**：`DELETE /api/taifu/thread` 后记忆为空，下一问的提示词里不再出现上一段。
- [ ] **AC-7 不回归**：r77/r78/r79 的引用白名单、页面上下文、锚点、两步清空、空档案出口全部不变；两端全绿。

## 已知限制

- 记忆是**滚动重写**的：每一轮由模型把「旧摘要 + 最近 6 条」合并成新摘要。若模型某一轮写得潦草，损失不可逆（旧摘要已被覆盖）。
- 记忆只有一段、不区分话题：中途换话题（先问短板、再问简历润色）会在同一段摘要里混着。
- 240 字是硬上限：极长的背景（例如用户完整讲了一遍转岗经历）只能保留要点。
- 不做记忆的「可信度」分级：摘要里可能有模型自己的措辞偏差，它与档案冲突时靠系统提示词要求「以档案为准」，没有程序级校验。
