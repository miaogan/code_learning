## 团队约定与技术栈

- 品牌与路线（2026-11-10 · r56 落定）：当前产品名「逃跑计划 / Escape Plan」，定位是**外包工程师的跃迁工作台**，主攻 **AI 应用 / Agent 后端**。品牌文案唯一来源 `frontend/src/lib/brand.ts`；叙事遵循「真实经历盘点 → 能力验证 → 项目证据补强」。ACP 只是知识补充，不将刷题、模拟评测或 dry-run 包装成生产经验或录用保证。历史任务夹、存储键、Cookie、路由、Docker 卷名保留旧标识以确保兼容，不做全局机械替换。下阶段方向是「目标岗位差距 + 项目工程证据 + 面试表达」的跃迁档案，**本轮未实现该看板**。

- 技术栈基线：Web 应用 = React + Vite（TypeScript）前端 / Python FastAPI 后端；AI 能力统一由服务端调用模型 API，Key 只经服务端 `.env` 注入，前端源码与构建产物中不得出现 Key。
- 数据落盘基线：首版用本地 SQLite 单库（`backend/app.db`），不引入外部数据库与云存储；**题库自 r6 起由 SQLite 的 `questions` 表承载（`backend/app/seed/questions.json` 退为唯一导入源，幂等导入不覆盖已有行）**，课程清单仍以服务端 JSON 文件维护。
- 文档基线：每个需求一个不可变任务夹 `docs/teamflow/<yyyyMMdd-rN-slug>/`，跨需求约定与待办只写 `docs/teamflow/memory.md`。
- 模块边界（2026-10-31 脚手架落定）：`frontend/` 只经 `src/api/client.ts` 出网（页面不直接 fetch）；`backend/` 路由层只做参数与错误映射，业务在 `app/services/`；画像 / 试卷 / 报告等结构化产物以 JSON 文本列入库，校验交给 pydantic（`app/schemas.py`）。
- 契约规则：JSON 字段名一律 snake_case；改字段必须同时改 `backend/app/schemas.py` 与 `frontend/src/api/types.ts`；错误统一为 `{ "error": { "code", "message", "retryable" } }`，message 中文且不含路径/堆栈/端点/Key。
- 视觉真源：`docs/teamflow/20261031-r1-dev-skill-coach/DESIGN.md` §0 的 token 与几何（40 按钮 / 24 徽章 / 96 磁贴 / 132 课程卡 / 128 textarea / 64 与 56 环）；实现只许引用 `frontend/src/styles/tokens.css`，改尺寸必须重算并回写设计文档。
- 反馈约定（2026-10-31 · r2 落定）：**成功用 Toast（唯一出口 `frontend/src/components/ui/Toast.tsx`，右下 24、`--elev-2`、2s）**，**失败一律页内 `InlineError`（中文原因 + 重试），禁止只用 Toast 承载失败**；报告类文本（复制/导出）只能取自 `api.reportMarkdown`（后端 `services/markdown.py` 单一渲染源），前端禁止二次拼串或裁剪。
- 记忆约定（2026-10-31 · r3 落定）：画像恒为**单一当前画像 + 增量合并**（同一能力项（归一后）证据累积、旧证据不删、消失项标 `status=historical` 且不参与出题/诊断）；成长记忆唯一来源是成长时间线表与 `GET /api/timeline`，事件指标必须复用既有 service（`history` / `diagnosis`）计算，前端不得自行做减法或二次拼装。
- 简历润色约定（2026-10-31 · r3 落定）：润色只在 `backend/app/services/resume_polish.py` 单一入口（路由与页面零提示词），为其被诊断报告复用留出入口；建议文本必须逐字带原句溯源，数字/专名的幻觉由后置校验降级为「仅措辞建议」、缺数值写 `〈待补充〉` 不编造；**「原文」类视图与导出文件名一律取服务端字段**（`PolishResponse.resume_text` / `file_name`，源自 `documents.text` / `documents.file_name`），禁止用建议句拼接重建正文、禁止前端自造或按日期臆造文件名（r4 定稿，2026-11-01）。
- 模拟面试约定（2026-11-01 · r5 落定）：面试是**多轮对话流**（面试官逐条发言、基于上一答追问/澄清/施压），不再一次性返回题目列表；每题（含追问）独立 0–10 评分 + ≤120 字点评，写入 `runs.payload.questions[]`——**该数组是会话唯一真相**，不另存 messages 副本；题号 `iq-N` 递增且刷新不变，追问额外带 `parent_id`；开局计划必须过 `rules.py` 配额闸门（≥8 题 / 技术≥5 / 项目≥3 / 挑战≤20%），不合格 502 且不静默补题。每场面试四项设定（目标岗位自由文本 / 工作经验：应届、1-3年、3-5年、5-10年、10年以上 / 面试市场：国内、北美、欧洲、其他 / 公司规模：大厂、中型、初创）随 `payload.settings` 落库（**不建表**）、必须进入每一轮提示词并真实改变出题口径，**临时设定永不写回画像**；单轮「提交→出分」沿用 15s 预算（`SCORING_TIMEOUT_S=14`），超时整轮 503 且零副作用。
- 笔试组卷与熟练度约定（2026-11-01 · r6 落定）：题库四维（`direction` / `kind` / `difficulty`(basic·intermediate·challenge) / `essentiality`(must_know·advanced·nice_to_know)）闭集集中在 `rules.py`，`schemas.py` 与 `types.ts` 逐字对齐；每题单用户熟练度记录（作答事件支撑**真实滑动窗口**：默认 30 天内答对 ≥2 次且最近一次正确＝熟练，超窗或最近答错即回流；简答题不计分故永不参与熟练判定），阈值只在 `config.py` 单一出处。组卷＝「可考池 − 熟练题 − 最近 3 卷已出题」内同相关度同难度档**随机抽题**，结构闸门（10–12 题 / 客观 ≥8 / 挑战 ≤20% / ≥2 个方向）必须恒定；不足时按唯一阶梯逐级放宽：L1 基线 → L2 回流已熟练 `must_know` → L3 回流其他熟练题 → L4 放松近 3 卷排除 → L5 跨方向补 → L6 全库，**任何一层都不得因过滤返回 400**；每次出卷把 `stage`/`filtered_count` 记进 `runs.payload`，旧 payload 读侧给默认值。判分仍纯本地零 AI、10s 内出分。
- 练习与题库扩容约定（2026-11-01 · r11 落定）：题库在 r6 四维之上加**第五维** `language`（闭集 `""/python/java/go/html/css/js/ts/vue3/react`，空串＝通用/算法）与方向归属（前端 html/css/js/ts/vue3/react、后端 python/java/go），闭集与归属单一出处在 `rules.py`，`language` **只作筛选维度、不参与笔试组卷相关度**；题型只做**选择与判断**（`kind` 闭集扩为 `single/multiple/judge/text`，**不做填空 blank**）——`judge` 复用「两选项单选」结构（`options` 恰 2 个、`answer` 指向其一、题面为限定条件明确的陈述句），渲染走既有单选分支、判分仍走 `grade_objective()` 集合相等，**全库只许一个客观题判分函数**；练习题单只收客观题 `kind ∈ {single,multiple,judge}`，存量 12 道 `text` 不进练习池；练习作答写入 r6 同一张 `question_attempts`（`run_id=practice:<session>` 命名空间，表上增 `source` 列区分 exam/practice），**熟练度公式与阈值零改动**（练熟即不再考是有意口径）；题面质量由结构化校验兜底（answer⊆options、解析非空≥10 字、同语言归一化题干去重 0、每语言 20 道且分布落闸门），新题一律 seed JSON 固化后幂等导入，运行时零 AI。
- 题库外部素材合并约定（2026-11-02 · r12 落定）：外部素材一律先落 `docs/question-bank-staging/`（提交进仓库，作为可复现输入），再由离线工具 `backend/app/services/question_merge.py`（`--check` / `--write` / `--rollback`）归一化 + 去重 + 标来源后写入 `backend/app/seed/questions.json`，**运行时零 AI、种子仍是唯一导入源**；归一化/去重常量只在该模块（2-gram Jaccard 0.62、`SOURCE_PRIORITY=tiji>local100>iq380>fe-interview`，同源取解析更长者、再按题干 sha1 定序），既有 seed 行**只增不删**；`source` 进种子与 `questions.source` 列但**不进 HTTP 契约**（schemas.py/types.ts 零改动），存量 260 道保持缺省 `'seed'`（显式写会与既有库分叉）；判定幂等的唯一标准是 `question_merge --check` 重新生成与已提交 seed **逐字节 0 差异**；外部素材必先核许可——MIT 需 `NOTICE-<source>.md`（全文 + 上游 URL + 改写说明），GPL / 无 LICENSE 一律不引入。
- 题库位置均衡约定（2026-11-02 · r13 落定）：seed 的选项顺序与答案 key 一律由 `backend/app/services/question_shuffle.py` 在 `question_merge.build_seed()` 末尾**确定性重排**（答案位置＝按 id 哈希定序后轮转填到当前计数最低的位置，实测单选 A/B/C/D=139/138/137/137）；**判断题不改选项**（恒 `A.正确/B.错误`），只按显式 `_JUDGE_FLIPS` 表（29 条、绝对映射保证幂等）改写陈述极性使 A/B=78/78；解析里「X 项 / 选项X / 『字母+判定词』/『A、B、D』」按同一映射同步重写，**无法可靠判角的题（实测 106 道）不打乱**（避免把 `C 语言`、`C++`、`ACID`、`MAC` 误映射）；写盘唯一者仍是 `question_merge`（`--check` 逐字节 0 差异是唯一幂等判据，`question_shuffle --write` 委托它）；冻结基线常量已从 `R11_SEED_SHA256` 迁移到 r13，判分/组卷/熟练度/契约零改动。
- 题库均衡收口约定（2026-11-02 · r14 落定）：补 r13 四条 P3，不改 HTTP 契约与运行时行为语义——①`ensure_seeded()` = `import_seed()`（只增）+ `refresh_from_seed()`（`repository.refresh_questions()` 只覆写**已存在同 id 行**、绝不新增、逐字段比对后只写差异、库内一致时恒 0），启动时把已部署 `app.db` 的旧选项顺序/旧判断题极性刷成当前 seed，历史 `question_attempts` 只存 `correct` 不受影响；②`question_shuffle.LENGTH_REWRITES` 40 条**绝对映射**（`before`→`after`）自动压缩 >3× 的正确项，`stale`（正确项既非 before 也非 after）非空即红，门禁 `MAX_LONG_ANSWER_COUNT=0`、2–3× 只抽检（`LENGTH_RATIO_SPOTCHECK=2.0`）；③`JUDGE_FLIPS` 38 条双向翻转（默认 A→B、`"answer":"A"` 表 B→A），`JUDGE_FLIP_COUNT` 直接等于表条数；④轮转分配按 `language` 分桶，门禁逐语言复算（`MIN_SINGLE_SAMPLE_PER_LANGUAGE=20` 落 20%–32%、`MIN_JUDGE_SAMPLE_PER_LANGUAGE=6` 落 40%–60%），`metrics.single/judge.by_language` 必须与实时重算逐桶一致。冻结基线 `R13_SEED_BYTES=191135` / `R13_SEED_SHA256=017e6777…aad4c7` 只锚前 260 行存量块；幂等判据仍是 `question_merge --check` 与 `question_shuffle --check` 双 0 差异。
- 题库正文清理约定（2026-11-02 · r15 落定）：题干/解析不得含素材编辑用语「参考答案要点」（它会向考生泄露「由参考答案反向加工」的出题元信息）——由 `question_merge.sanitize_text()` 在 `build_seed()` 的 `merge_rows()` 之后、`question_shuffle.apply()` 之前做**固定串整串替换**（`_TEXT_REWRITES`：题干→「要求」、解析→「参考要点」，不做正则/上下文推断、不顺手润色），返回新字典不改入参，替换后不含原串即幂等；门禁在 `test_r12_question_merge.py`（落盘 seed 的 `prompt`/`explanation` 命中即红、与「未清理版本」逐题对拍断言只动该串、命中数恒 60），素材若重新导入导致命中数变化必须复核口径并留痕。
- 题库素材留痕与 id 前缀约定（2026-11-02 · r16 落定）：种子 id 前缀唯一真源是 `question_merge.ID_PREFIX` —— `tiji-` / `l100-` / `iq380-` / `fei-`（`iq380-` 刻意避开面试发言 `iq-` 域），**四前缀不得改名**（改名会让 `--rollback` 与已部署库既有行分叉）；文档口径以 ARCHITECTURE §3.4.2 为准，历史任务夹里的 `iq-NNN` 属笔误、不再作为依据；`docs/question-bank-staging/` 必须同时具备两类凭证——自建素材的 `PROVENANCE.md`（来源性质 / 生成方式 / 日期 / 结构 / 回滚口径）与第三方素材的 `NOTICE-<source>.md`（MIT 全文 + 上游 URL + 改写说明），该目录是**输入真源**，改素材必须同步凭证并重跑 `question_merge --check`（0 差异）。
- 契约可空口径（2026-11-01 · r8 落定）：提示词允许的 `null` 必须被契约接受——`ProfileProject.role/period` 为 `str | None = None` 且 `frontend/src/api/types.ts` 逐字镜像 `string | null`，两侧靠 `test_r8_profile_nullable_mirror` 静态门禁牵制，任一侧回退即红；同口径的 `skills`/`tech_stack`/`projects`/`bullets` 的 `null`/缺键只在 `ProfileDraft` 的 before-validator 归一为 `[]`（`Profile` 继承即覆盖草稿/响应/存量三条路），**不得**用空串伪装「未知」、不得 `extra="allow"`、不得放宽 `name`/`source_quote` 必填；下游一律显式承载 `null`（数字采集 `period or ""`、面试输入省略 `None` 键、合并用 `_prefer_text` 空值不覆盖已知值），前端空值归一单点收敛在 `src/lib/profileText.ts` 的 `textOrEmpty`/`joinMeta`。
- 模型供应商切换约定（2026-11-01 · r9 落定）：AI 供应商走「配置档 + `AI_PROVIDER` 选择」——空值＝legacy（直读 `AI_BASE_URL`/`AI_MODEL`/`AI_API_KEY`/`AI_TIMEOUT_S`，行为零变化），否则按 `AI_<DEEPSEEK|LMSTUDIO>_{BASE_URL,MODEL,API_KEY,JSON_MODE,TIMEOUT_S}` 取用；**具名档的 base_url/model/key 一律不回落全局**（防把云端 Key 发给本地端点），`AI_JSON_MODE` 闭集只收 `json_object`(缺省)/`none`（`none`＝整键不发 `response_format`，供 LM Studio），空 key 省略 `Authorization`；`/health` 只暴露 `ai_provider`/`ai_model`/`ai_json_mode`（永不暴露 key），`health()` 必须 live `get_settings()`；`tests/conftest.py::tmp_db` 必须置空 `AI_PROVIDER` 与各档变量（否则宿主 `.env` 会让既有用例集体变红），门禁不得依赖本机 LM Studio（真实链路用 `AI_LIVE` 开关 + QA 脚本）；**数值型档位**（`AI_TIMEOUT_S`/`AI_MAX_RETRIES`/`AI_DEEPSEEK_TIMEOUT_S`/`AI_LMSTUDIO_TIMEOUT_S`）在 `.env` 里写成空值时按「未设置」回落字段默认值（`Settings` 的 before 校验器兜住），否则空串进 `float`/`int` 会在构造期抛错、整个后端起不来——字符串字段不适用该规则，它们的「空＝继承全局」是 r9 的真语义。
- 容器化交付约定（2026-11-01 · r10 落定）：生产形态＝两容器 compose —— `frontend`（nginx:alpine 托管 `frontend/dist`，同源反代 `/api`、`/health` 到 `backend:8000`）＋ `backend`（python:3.13-slim，**非 root** 跑 uvicorn，**不发布宿主端口**），宿主只暴露 `${WEB_PORT:-8080}`；SQLite 落命名卷 `skillcoach-data:/data`（`DB_PATH=/data/app.db`），**服务名/端口/卷名是跨需求契约**，改任一项必须同步 `docker-compose.yml` + 本夹 `DEPLOY.md` + `README.md`；配置唯一来源仍是 `backend/.env`（compose 用 `env_file` 引用且 `required:false`，**禁止把 Key 或 `AI_PROVIDER` 写进 compose 的 `environment`**，否则会冲掉 `.env` 的显式选择）；「默认走 DeepSeek」由 compose `command` 内的确定性解析实现（`AI_PROVIDER` 空且 `AI_DEEPSEEK_API_KEY` 非空→导 `deepseek`，否则维持 legacy 三件套，**任何路径都不许默认配置起不来**）；`.dockerignore` 必须挡 `.env`/`*.db`/`tests`/`__pycache__`/`node_modules-pnpm`，示例配置定名 `docker.env.example`（`.gitignore:42` 的 `.env.*` 会命中 `.env.docker.example`，且该名在 DSH 文件工具侧撞凭据围栏——两个原因都禁用旧名；改后 `.gitignore` 零改动）；前端只经反代（`VITE_API_BASE` 保持空），禁止硬编码后端地址；镜像内不得出现 `sk-`，门禁用 `docker history` + 镜像内 grep 双向核。
