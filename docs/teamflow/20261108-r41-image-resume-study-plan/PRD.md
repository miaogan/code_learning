# PRD · r41 图片简历入口 + 报告转 7 天学习计划

- 需求来源：用户提出「移动端漏斗第一关只认 PDF/DOCX」「报告闭环断在最后一步」两个痛点
- 任务夹：`docs/teamflow/20261108-r41-image-resume-study-plan/`
- 前置版本：r40（移动端可用性收口，视图 360–430 已可用）
- 本文件只定义**做什么 / 为什么 / 怎么判**；实现路径与代价见同目录 `TECH-PLAN.md`

---

## 0. 一句话目标

1. **A**：让用户在手机上「拍一张 / 从相册选一张」就能上传简历，后端把图片里的文字抽成正文，接进现有解析 → 画像 → 面试/笔试 → 报告链路；不落原图、不静默降级。
2. **B**：报告页把诊断结论直接排成**未来 7 天、按天分任务、带预计时长**的可执行学习计划，可打卡、可跨会话保留；打卡**不进**熟练度与成绩。

## 1. 现状与缺口

| 现状 | 缺口 | 影响 |
|---|---|---|
| `POST /api/resumes` 只接受 `.pdf/.docx/.txt`，`parser.py` 用 pypdf / python-docx 抽文本层 | 手机相册里的截图、拍照、招聘 App 截图全部被拒 | 移动端漏斗第一关直接流失 |
| 现有 AI 调用 `complete_model` 只发纯文本 `messages` | 没有多模态请求能力 | 图片无法送模型识别 |
| 报告页已有 `WeekPlan`（7 天 × 3 个短板任务，外部课程链接，按天打卡存 localStorage） | 无时长、无章节/小节映射、无依赖顺序、只有 3 天有内容，剩余 4 天是固定通用任务 | 「今晚学什么、学多久」仍需用户自己排 |
| 学习进度口径：只记「读过」（`sc.learn.<userId>`），不计成绩 | — | 计划打卡必须沿用该口径，不得新增评分入口 |

## 2. 功能 A：图片简历上传

### 2.1 用户故事

- 作为手机用户，我在上传页能直接「拍照」或「从相册选图」，不用先想办法把截图转成 PDF。
- 作为上传了两张图（简历正面 + 项目经历页）的用户，我能一次提交 1–3 张，系统合并成一份正文。
- 作为拍糊了的用户，我能看到「识别到的文字太少，请重拍」这类**可行动**的反馈，并能一键重试。

### 2.2 范围（本轮做）

1. 上传页新增图片入口：**拍照**（`capture` 提示后置摄像头）+ **从相册选**（可多选，上限 3 张）。
2. 图片本地预处理：方向校正 + 最长边压到 1600px + 统一转 JPEG（降低 token 与 HEIC 兼容风险）。
3. 单次提交 1–3 张，**合并为一份简历**（一个 `resume_id`），进入既有画像生成与后续全部链路。
4. 进度可见：沿用现有环形进度 + 阶段文字（新增「识别图片中」阶段）。
5. 失败可重试：沿用 `InlineError`（中文原因 + 重试按钮）；Toast 只用于成功类提示。
6. 质量兜底：识别出的正文低于阈值时明确提示重拍或改用 PDF，**不静默失败、不静默降级**。
7. 隐私：图片字节只在内存中存在，**不落盘、不入库**；入库仍只有抽取正文 + mime + 文件名。

### 2.3 非目标（本轮不做）

- 不做扫描件 PDF 的 OCR（PDF 无文本层仍按既有 `PARSE_FAILED` 处理）。
- 不做「图片 → 结构化字段（教育/项目）」的二次抽取，只产出正文文本。
- 不做拍照实时裁边/透视矫正（只做 EXIF 方向校正与等比缩放）。
- 不做 HEIC 服务端解码（由前端统一转 JPEG；前端转不了时给明确文案）。
- 不做批量超过 3 张。

### 2.4 验收标准（AC）

| 编号 | 验收标准 | 判定方式 |
|---|---|---|
| A-1 | 360–430 宽下，上传页可见「拍照」「从相册选」两个入口，点按区域 ≥44px | 真机 + 片段扫描 |
| A-2 | 拍照/选图后能看到缩略图，可删除、可追加（上限 3 张），超限有中文提示 | 真机操作 |
| A-3 | 单张 ≤10MB、总量 ≤10MB、仅 JPEG/PNG/WebP 进入识别；超限/格式不符有中文提示且无重试按钮 | 真机 + 接口 |
| A-4 | 1 张图片走完全流程：上传 → 识别 → 画像 → 可进面试 | 端到端 |
| A-5 | 2–3 张图片合并为**一份**简历（一个 `resume_id`），画像只生成一次 | 接口返回 + 页面 |
| A-6 | 识别字数 < 阈值时提示「识别到的文字太少，请重拍或改用 PDF」，带重试 | 用空白图/严重模糊图 |
| A-7 | 视觉能力未配置时返回明确中文错误「图片识别未开通，请改用 PDF 上传」，**不静默降级** | 关掉视觉配置后复测 |
| A-8 | 图片字节不落盘（进程临时目录与 `documents` 表都无图片二进制） | 查库/查目录 |
| A-9 | 所有错误提示不含路径、端点、Key、堆栈 | 逐条走错误分支 |
| A-10 | 桌面端不受损：原 PDF/DOCX/TXT 路径与文案不变 | 回归 |

### 2.5 关键产品决策（需拍板）

| # | 决策 | 建议 | 备选 |
|---|---|---|---|
| D1 | 识别所用供应商 | **复用现有 DeepSeek 账号的 `deepseek-flash` 视觉模型**（同一 base_url、同一 Key；见 TECH-PLAN §2 的成本核算） | 第三方云 OCR（新增供应商 + 隐私外发 + 计费）；本地 OCR（质量不可控，否决） |
| D2 | 单次图片上限 | 3 张（覆盖「正面 + 项目页」「正 + 反」） | 1 张（严格单文件，但无法满足多页需求）；5 张（成本与失败面变大） |
| D3 | 合并策略 | 按用户选择顺序拼接，段间插入 `【第 n 页】` 标记 | 逐张独立建简历（会导致画像多次生成，否决） |
| D4 | 质量阈值 | 抽取正文 < 60 字 → 判为「识别不足」 | 用置信度（供应商无逐字置信度，不可用） |

## 3. 功能 B：报告 → 7 天可执行学习计划

### 3.1 用户故事

- 作为刚看完报告的用户，我能选「每天 15 / 30 / 60 分钟」，直接拿到 7 天日程，而不是自己从短板列表里挑。
- 作为用户，我点进每天的任务能**直接跳到对应教程章节/小节**（不是外链文章）。
- 作为用户，我打卡后能看到「第 3/7 天完成」，下次打开还在；但我知道这**不影响**我的分数与熟练度。

### 3.2 范围（本轮做）

1. 报告页的 `WeekPlan` 升级为「学习计划」：
   - 顶部时长选择（15 / 30 / 60 分钟，默认 30）；
   - 7 天，每天 1–3 个任务，每个任务含：标题、类型（读教程 / 练题 / 回看诊断）、预计分钟、来源短板、跳转链接；
   - 任务按「短板严重度 → 同方向难度前置（基础 → 进阶 → 高级）→ 掌握率低优先」排序；
   - 每天总时长不超过所选预算（放不下则顺延至次日，7 天排不满时末日聚合）。
2. 打卡：按任务粒度（不是只按天），已完成任务可撤销；进度条显示「已完成 n / 总 m 项 · 约 x 分钟」。
3. 跨会话保留：同账号同浏览器重开仍在；切报告/切页面不丢。
4. 降级：
   - 无 `weakness_map` → 退用 `shortfalls`；
   - 两者都空 → 不硬编「假短板」，显示「本次数据不足以定位短板」+ 3 个明确标注为「通用建议」的任务；
   - 方向匹配不到站内章节 → 保留练题任务，章节位显示「暂无对口章节」；
   - 报告未生成 → 不渲染该模块。
5. 口径声明：打卡**只**写本地学习计划状态，不调用画像/报告/评分接口，不改熟练度；页面明确一行「打卡仅记录学习动作，不改变诊断分数」。

### 3.3 非目标

- 不做日历提醒/推送、不做 ICS 导出。
- 不做后端持久化（本轮不做跨设备同步；见 TECH-PLAN 的 B1/B2 取舍）。
- 不做 AI 自由生成计划（确定性映射足够，且避免不稳定的「编造章节」）。

### 3.4 验收标准（AC）

| 编号 | 验收标准 | 判定方式 |
|---|---|---|
| B-1 | 报告页可选择 15/30/60 分钟，切换后计划即时重排，单日总时长不超预算（允许 ±0） | 单测 + 真机 |
| B-2 | 7 天每天都有任务，且至少 3 天任务来自真实短板（有短板数据时） | 单测断言 |
| B-3 | 每个教程类任务都能跳到真实存在的章/小节（404 视为失败） | 单测遍历 + 点按 |
| B-4 | 排序：高严重度短板的任务排在前 3 天；同方向内基础章先于进阶章 | 单测断言 |
| B-5 | 打卡按任务粒度，可撤销；刷新/重开浏览器后保留 | 真机 + 单测 |
| B-6 | 进度文案正确：已完成 n / 总 m 项、约 x 分钟 | 页面核对 |
| B-7 | 无诊断数据时走降级文案，**不出现**编造的短板名 | 空账号 |
| B-8 | 打卡不改变 `profile` / `report` 任何字段，也不调用评分端点 | 查网络请求 + 接口 |
| B-9 | 360–430 宽下计划卡单列、任务行可点 ≥44px、不横向溢出 | 真机 + 溢出扫描 |
| B-10 | 切换账号后看不到他人计划 | 双账号 |

## 4. 移动端优先（两功能共同）

- 新增 UI 一律 360 起可用：单列、无横向溢出（`overflow-x: clip` 兜底下仍要逐元素扫描）、触控目标 ≥44。
- 样式只用 `tokens.css` 变量；新增尺寸须在 `TECH-PLAN` 的「尺寸推导」里算清并回写设计文档。
- 上传页图片入口在窄屏不能把主 CTA 挤出首屏；计划卡在窄屏不出现「横向滑动看表格」。

## 5. 契约与口径约束（不可破）

| 约束 | 落法 |
|---|---|
| 字段双向同步 | 新增/变更字段必须同时改 `backend/app/schemas.py` 与 `frontend/src/api/types.ts`，snake_case |
| 错误 envelope | 一律 `{ "error": { "code", "message", "retryable" } }`，message 中文、不含路径/端点/Key |
| 错误码闭集 | **优先复用**既有码（`AI_UNAVAILABLE` / `VALIDATION_ERROR` / `PARSE_FAILED`）；确需新码时同步更新 ARCHITECTURE §3.3 |
| 模块边界 | 路由层只做参数校验与错误映射；识别、排程、匹配逻辑在 `services/`；AI 调用只在服务端 |
| 隐私 | 不落原图；只存正文；日志不打印文件名以外的用户内容 |
| 学习口径 | 只记「读过/做过」，不进评分与熟练度 |
