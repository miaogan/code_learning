# r108 · 跃迁档案看板

## 用户目标

r56 品牌改版明确把「跃迁档案」列为下一阶段：把**目标岗位差距、项目工程证据与面试表达**汇成一份可复核的看板，让外包工程师把「从交付任务到证明能力」的跃迁落到具体证据上。本需求落地这一看板。

## 已确认范围

- 单页看板 `/leap`，侧栏「工具」组新增「跃迁」入口（桌面 + 移动顶部同时生效）。
- 服务端一次聚合三块，零 AI、零新表、零重算：
  1. **目标岗位差距** = 最近一份诊断报告的 `role_fit`（差距在报告生成时已算好）；
  2. **项目工程证据** = 画像项目逐条（bullets + 溯源条数）+ 落库规模事实 + RAG / 技术雷达状态；
  3. **面试表达** = 最近已评分的作答发言（分数 / 点评沿用当场写入值）+「问题—方案—指标—踩坑」文本自检。
- AI 上下文：太傅页面白名单新增 `/leap`；教练 Agent 新增 `read_leap_archive` 只读工具（引用 `/leap`，产出 ref 令牌进白名单）。
- 顺带清理三项工程待办：课程外链点检、真实环境补测清单、多进程限流评估（结论落 `logs/teamflow/`，不进仓库）。

## 非目标（硬边界，继承 r56）

- 不虚构跃迁：模拟面试 / dry-run / 刷题量不包装成生产经验；文本自检**不是评分、不是能力结论**。
- 不新建数据库表、不重算岗位差距 / 熟练度 / 分数、不调用模型、不改既有 HTTP 契约字段语义。
- 不打 v0.3.0 tag / 不开 PR（本轮只做物料核对，公网验收 44/44 卡演示账号口令）。
- 不改既有样式行（tokens.css / base.css 仅 append）；不提交、不推送、不部署。

## 验收标准

1. 未登录访问 `/api/leap-archive` 被拒；登录后 200，三块结构齐全，空态给中文指引。
2. 有报告时岗位差距逐字段等于 `latest_report().role_fit`，前端零减法、不重排 `first_fix`。
3. 工程证据只列真实画像项目与真实行数，historical 项目保留但标注；空态不补 0、不造项目。
4. 面试表达只收录**已评分**发言（score 为数字），分数 / 点评逐字沿用写入值；四要素自检命中给中文提示且明说「非评分、非生产经验」。
5. 数据按账号隔离（service 层切换 ContextVar 后只读当前账号）。
6. 太傅识别 `/leap` 为页面上下文（仅用于理解指代，不是引用依据）；教练新工具空态不编造、有数据时引用都指向 `/leap` 且 ref 唯一。
7. 前端 typecheck / lint / test、后端 ruff / pytest 全绿；契约 `types.ts` 与 `schemas.py` 逐字段镜像。
