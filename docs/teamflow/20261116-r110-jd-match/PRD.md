# r110 · JD 岗位对位

## 用户目标

竞品调研里最值得借鉴的一条是 Jobscan / Teal / 牛客共同验证的闭环：用户不是缺「更多通用题」，而是想知道**这份 JD 要什么、我有哪些证据、差在哪里、下一步练什么**。本轮把这个闭环接到已有简历画像、岗位模型、医案报告与召对面试上。

## 已确认范围

- 新增 `/jd` 页面与侧栏「对岗」入口，桌面与移动顶部工具条同时生效。
- `POST /api/jd-match`：粘贴 JD（可选显式目标岗位）后，一次返回：
  1. 技术词清单：命中短语、JD 原句、画像档位、可引用简历原句；
  2. 缺口清单：严格区分「JD 写到但画像没证据」与「岗位模型要求但 JD 未直接写」；
  3. 目标岗位差距：按本次岗位现场对标（不改医案里已写入的报告）；
  4. 召对预设：岗位 / 方向 / 二级方向三项，一键带配置进入面试页。
- 面试页识别 `?target_role=&direction=&sub_direction=`，只预填配置，不替用户决定经验档 / 市场 / 公司规模；带 preset 时不自动接回旧在途会话。

## 非目标（硬边界）

- 零 AI、零新表、零百分比分数。RAG / DeepSeek Key 都不参与本轮。
- 不把「未找到证据」写成能力不足，不把模拟练习 / dry-run 写成生产经验。
- 不改报告写入口径，不改 `RoleFit` 既有字段，不重排 `first_fix`。
- 不做实时 copilot、语音分析、投递 CRM。
- 不提交、不推送、不部署。

## 验收标准

1. 未登录访问 `/api/jd-match` 被拒；登录后空 JD / 纯空白 JD 返回中文 400。
2. 无画像时仍能列出 JD 技术词，但所有条目标 `missing`，并提示先完成画像。
3. 有画像时，命中技术词逐条回传 JD 原句、画像档位与简历引用；短 ASCII 别名按词边界命中（`go` 不命中 `golang`）。
4. 缺口来源分成 `origin=jd` 与 `origin=role_model`，两者文案不混；没有 `source` 字段泄漏（遵守 r12 HTTP 契约门禁）。
5. 目标岗位显式输入优先于自动识别；未指定时按内置岗位模型名 / 常见简称 → 画像岗位 → 最近报告岗位的顺序识别。
6. 一键链接只带合法闭集值；面试页带入后不覆盖用户手改，也不自动恢复旧会话。
7. 服务层按账号隔离；响应不含 `score` / `match_rate` 等能力分字段。
8. 后端 ruff / 专项 pytest、前端 typecheck / lint / 构建 / 专项与全量测试通过（已知本机 health 启动竞态除外）。
