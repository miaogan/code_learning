# r111 · JD 缺口驱动的定向追问 + 表达复盘对照

## 用户目标

r110 打通了「JD → 证据 → 缺口 → 一键进召对」，但缺口只用于预填岗位 / 方向。本轮把它推到底：

1. **P1 定向追问**：从 `/jd` 带进召对的缺口技能，真正进入本场出题逻辑——主问题围绕缺口展开、追问沿缺口深挖（对标牛客类产品的「技术追问链」，但零 AI 新能力、只改提示词与契约）。
2. **P2 表达复盘对照**：跃迁档案「面试表达」块逐条显示本场缺口词在回答里是否被提到——把「练了什么」和「JD 差什么」放回同一屏，保持非评分口径。

## 已确认范围

### P1：缺口进入面试

- `InterviewSettings` / `InterviewSettingsPatch` 新增 `focus_gaps: list[str]`（最多 3 项），落 `runs.payload.settings`，永不写回画像。
- 服务端清洗口径：去首尾空白、去重、单条截 40 字、最多 3 项；存量 run 缺键按空列表补，四项既有语义不变。
- 出题提示词两条硬要求：
  - `focus_gaps` 非空时，前 `min(3, N)` 道 technical 题必须分别围绕缺口技能展开；
  - 追问优先沿当前题对应的缺口技能深挖（方案、指标与踩坑），不换题。
- `/jd` 一键召对链接追加 `focus` 重复参数（最多 3 个）；面试页 `presetFromParams` 解析后进入隐藏字段 `focus_gaps`，不在表单手改；`draftToPatch` 非空才下发（无缺口不带空键）；`previewLine` 显示「缺口：A / B / C」。
- 开局预览、preset 应用（同 URL 只应用一次、带 preset 不自动接回旧在途会话）沿用 r110 行为。

### P2：表达复盘对照

- `LeapExpressionItem` 新增 `focus_gaps` / `gap_hits` / `gap_misses`。
- 聚合时按场次 `settings.focus_gaps` 回读缺口词，用 `jd_match.term_in_text`（同一套别名 + 词边界）对照回答文本；命中 = 回答里出现了该词，不是掌握度结论。
- 存量 run（没有该键）三字段为空列表，如实展示、不补造。
- 前端 `gapCompareText`：本场缺口词非空才渲染对照行，文案明说「仅关键词对照，不是掌握度结论」。

## 非目标（硬边界）

- 零 AI、零新表、零评分。缺口命中不产生分数、不进报告、不改 `RoleFit`。
- `focus_gaps` 只影响本场出题，永不写回画像，不作为能力证据。
- 不做语音分析、实时 copilot、投递 CRM。
- 不改四项设置（经验档 / 市场 / 公司规模）的既有语义与默认值。
- 不提交、不推送、不部署。

## 验收标准

1. 带缺口开局：提示词里出现清洗后的缺口词；前几道 technical 题围绕缺口展开的指令生效。
2. 缺口清洗：空白项丢弃、超长截 40、去重、最多 3 项；`focus_gaps` 为空时提示词不出现缺口段。
3. 存量 run（无 `settings.focus_gaps`）读取、恢复、报告全部照旧，空列表不产生对照行。
4. 跃迁档案表达块：JD 场次的条目逐条给出命中 / 未提到；非 JD 场次不渲染对照；短 ASCII 别名仍按词边界（`go` 不命中 `golang`）。
5. `/jd` 链接 → 面试页预填 → 开局提交，全链路只带合法值；无缺口时不下发空键。
6. `schemas.py` ↔ `types.ts` 逐字段镜像；HTTP 契约无 `source` 字段（r12 门禁）。
7. 后端 ruff / 专项 pytest、前端 typecheck / lint / build / 专项与全量测试通过（已知本机 health 启动竞态除外）。
