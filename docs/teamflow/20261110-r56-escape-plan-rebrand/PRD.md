# r56 · 逃跑计划：品牌改名与跃迁路线

## 用户目标

将原「Skill Coach · 开发者能力提升教练」更名为「逃跑计划」。目标不是逃离某一家公司，而是摆脱长期外包交付带来的能力标签，向更高平台的 **AI 应用 / Agent 后端** 岗位跃迁。

用户已确认本轮范围：**改名并明确路线**，不一次性新增跃迁看板。

## 产品定义

> 逃跑计划：外包工程师的跃迁工作台。用真实经历定位差距，用技术测评验证能力，用项目证据支撑下一次职业选择。

### 原则

1. **证据优先**：简历技能与项目逐条溯源，测评短板指向具体题目；不把标签当能力。
2. **项目高于证书**：ACP 六大知识领域作为知识体系补充，不把题量或认证承诺写成工作能力。
3. **工程结果可复现**：优先沉淀异常兜底、质量评测、检索增强、可观测性与性能口径，而不是堆砌 RAG / Agent 名词。
4. **不虚构跃迁**：模拟数据、离线评测、dry-run、练习成绩都不是生产经验或录用保证。

## 路线与现状

| 跃迁阶段 | 已有事实 | 下一阶段 |
| --- | --- | --- |
| 盘点外包经历 | 简历/图片解析、技能与项目原文溯源、历史能力项保留 | 选择最能证明工程价值的项目 |
| 验证工程能力 | 多轮模拟面试、1224 道题库、60 道 ACP 原创题、趋势与错题 | 围绕目标岗位做差距解释 |
| 补项目证据 | 可靠性故障注入、离线评测、检索增强、日志与性能基准 | 汇聚成可复核的「跃迁档案」 |
| 练面试表达 | 岗位匹配、报告与简历润色 | 以「问题—方案—指标—踩坑」打磨项目陈述 |

## 本轮范围

- 前端品牌单点：`lib/brand.ts`；顶栏、登录页、首页与 HTML 元信息统一。
- 登录页传达「从交付任务到证明能力」；首页呈现当前路线与五步「盘点 → 验证 → 补强」路径。
- 包名改为 `escape-plan-frontend`；API 标题与润色导出品牌同步。
- 更新 README、AGENTS、ARCHITECTURE 与产品记忆，区分已有能力与后续规划。
- 不改路由、存储键、数据库、Cookie、HTTP 字段、题目、历史任务夹或 Docker 卷名。

## 非目标

- 不承诺进大厂、不贬损外包经历、不默认用户已具备 RAG / 多 Agent 生产经验。
- 不新增目标岗位编辑器、行动看板、在线模型调用或新数据库表。
- 不整体重写视觉，不修改仓库名、远端地址或兼容标识 `sc-*` / `skillcoach-data`。

## 验收

1. 当前品牌展示为「逃跑计划」，登录与首页明确外包跃迁及 AI 应用 / Agent 后端路线。
2. 保留简历上传、测评、学习、练习与历史功能及数据兼容。
3. 品牌字符串单点维护；当前运行时代码不残留面向用户的 Skill Coach。
4. 前端 typecheck / lint / test / build、后端 ruff / pytest 通过，记录实际验证结果。
