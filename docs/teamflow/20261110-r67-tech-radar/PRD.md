# r67 技术雷达（先锋 / 国子监）· PRD

> 需求：能主动收集新的技术、评估这门技术需不需要学；如果需要，自动整理学习内容和练习题。
> 页面命名：**先锋**（技术清单与评估结论）、**国子监**（样例生成进度与审阅入库）。

## 1. 背景与目标

用户要的不是「AI 新闻聚合器」，而是**技术选型决策辅助**：每天三个节点自动看一遍外部世界，给出「这门技术对『高级 AI 应用 / Agent 后端』岗位该不该学」的结论，并只对「值得学」的项产出可用的学习材料与练习题样例。

目标（按优先级）：

1. **可复算的评估**：每条技术有 `结论 + 四维档位 + 理由 + 证据链接`，同输入同输出，能追问「凭什么」。
2. **异步生成、人工入库**：生成慢（模型调用），必须后台跑、进度可见；产出的样例**默认不进正式内容**，由人点「扩充入库 / 废弃」。
3. **零成本可用**：没有模型 Key、没有外网也能端到端演示（离线样本 + 规则评估兜底）。
4. **不污染既有基线**：官方的 40 章静态教程、1224 题正库、笔试组卷结构、熟练度统计全部不被动。

## 2. 用户与场景

| 场景 | 用户动作 | 系统行为 |
|---|---|---|
| 每天 8 / 12 / 18 点 | 无（自动） | 后台跑一轮采集 + 评估，落库 |
| 想知道「这波新技术里我该学啥」 | 打开**先锋** | 按结论降序的清单，每行给四维与理由 |
| 手动补一次 | 点「立即采集」 | 同步跑一轮（采集 + 规则评估，最坏 90s 硬上限） |
| 对某条技术感兴趣 | 点右侧「生成样例」 | 202 受理，后台异步生成章节草稿 + 题目样例 |
| 看生成到哪了 | 打开**国子监** | 任务列表（进度 / 阶段 / 耗时 / 来源技术） |
| 样例满意 | 点「扩充入库」 | 通过自检的题目写入**练习池**（仅练习池），章节草稿存档可见 |
| 样例不满意 / 判断跑偏 | 点「废弃」 | 草稿作废，不写入任何正式内容 |

## 3. 范围

**做**：定时采集（GitHub Search API / Hacker News / arXiv / OpenAI Blog / Google AI Blog / 手动录入）、评估（四档结论 + 四维 1–5 档）、异步生成（章节草稿 + 题目样例）、两页展示、扩充入库 / 废弃、来源连通性面板、离线样本兜底。

**不做**（刻意排除，写进验收）：

- 不发布到 B 站 / 知乎 / 掘金等站外平台（无账号授权，且对抗风控不是工程亮点）。
- 不把生成的章节**自动并入**官方 40 章静态教程（`frontend/src/content/tutorials/` 是代码，内容须经 review）。
- 不把生成的题目**自动进**笔试组卷（会改动现有题量统计、熟练度基线、卷面结构的稳定性）。
- 不引向量库、不做语义检索（本轮评估结论由结构化信号 + 模型判断给出，够用且可解释）。
- 不做多副本调度租约（单进程 uvicorn，无 `--workers`，属过度设计）。

## 4. 核心流程

```
[8:00 / 12:00 / 18:00]  run_round()
        ├─ 采集：6 源并发，单源 8s 超时，失败不连坐
        ├─ 归一化：统一成 {slug, name, direction, url, summary, signals}
        ├─ 去重入库 radar_techs（slug 唯一，已有则只更新 last_seen）
        ├─ 快照 radar_snapshots（stars / forks / pushed_at）
        └─ 评估 radar_assessments（结论 + 四维 + 理由 + 证据 + 可复算指纹）

[先锋页] 点「生成样例」 → 202 + job_id
        └─ 后台：模型先生成章节草稿（≥3 小节，末节带自测）
                再生成题目样例（3–5 道，答案自检一致才留）
                进度写 radar_jobs（国子监轮询可见）

[国子监页] 样例审阅
        ├─ 扩充入库 → 题目写 questions(source='radar') → 只进练习池
        └─ 废弃 → 草稿归档，不入任何正式内容
```

## 5. 两个页面

### 5.1 先锋（`/pioneer`）

- 顶部：本轮采集状态（时间 / 源成功数 / 是否降级 / 「立即采集」按钮）。
- 列表每行：技术名 + 来源 chip + 方向 chip + **结论**（必学 / 值得了解 / 观望 / 跳过）+ 四维迷你条（岗位相关度 / 行业采用度 / 成熟度 / 学习成本，1–5）+ GitHub star 增速 + 一句话理由。
- 行右侧：主按钮「生成样例」；生成中显示「生成中 · 前往国子监」；已生成显示「查看样例 →」。
- 点行展开：完整理由、证据链接（只允许本轮采集到的链接）、快照历史。
- 排序：结论权重（必学 > 值得了解 > 观望 > 跳过）→ 岗位相关度降序 → star 增速降序。

### 5.2 国子监（`/guozijian`）

- 任务列表：技术名 / 状态（排队 / 生成中 / 已完成 / 已入库 / 已废弃 / 失败）/ 阶段（章节 → 题目 → 完成）/ 进度条 / 耗时。
- 展开已完成任务：
  - 章节草稿：标题 + 小节列表（只读预览，界面上明写「草稿，未并入官方教程」）。
  - 题目样例卡片：题干 / 选项 / 答案 / 解析 / 自检状态（`一致` / `不一致已丢弃`）。
- 底部两个按钮：**扩充入库**（主）、**废弃**（次）。

本轮补充解释（如与你想的不一致请直接说）：

- **5.1 的两个基础功能**：`扩充入库` = 把样例并入站内（题目→练习池、章节草稿→存档可见，**不并入官方 40 章**）；`废弃` = 整份草稿作废。二者是互斥终态。
- **6.4 的落地边界**：本轮只做「评估吃画像」，**不改** r58 已稳定的画像雷达七轴口径（把雷达结果并入「广度 / 学习力 / 技术力」会改动既有 24 条单测的定义，建议下一轮单独做）。

## 7. 验收标准

- AC-1 无网络 + 无模型 Key 时，`RADAR_OFFLINE=1` 下能跑通一轮并在先锋页看到带四维的清单。
- AC-2 单源失败（500 / 超时）时，本轮仍成功落库，且来源面板标记该源失败、本轮标 `degraded`。
- AC-3 同一 `tech_slug` 同时只能有 1 个未终态生成任务（重复点击返回同一 job_id，不重复烧 token）。
- AC-4 生成任务失败/超时有中文原因，且不会永远停在「生成中」（读路径惰性清扫）。
- AC-5 扩充入库后，题目出现在练习组卷池（`practice_pool()`），**不出现在**笔试卷（`exam_pool()`）。
- AC-6 答案自检不一致的题目不入库，并在样例卡上标注已丢弃。
- AC-7 废弃任务不写入 `questions` 与任何教程内容。
- AC-8 调度纯函数 `next_run_at` 跨日正确（18:00 的下一次是次日 08:00），时区固定 +08:00。
- AC-9 生成/入库/废弃均按账号隔离，未登录 401。

## 8. 风险与边界

| 风险 | 处置 |
|---|---|
| 上游慢（实测 2.6–10.5s）与 502 | 全源并发、单源 8s 超时、单源失败不连坐、本轮 `degraded` 标记 |
| GitHub 需要 token（未认证配额低） | 支持 `GITHUB_TOKEN`；无 token 时退化为单次检索 + 保守频率 |
| 刷 star 仓库（实测出现 30 万 star 且当年新建的仓库） | 快照取 `created_at`，star 增速按天计算并对「新建即巨量」标 `suspect`，结论降一档 |
| 模型产出幻觉引用 | 证据白名单：只保留本轮采集到的 URL；越界链接丢弃并计数 |
| 生成内容质量不可控 | 默认只产出「样例」，必须人工「扩充入库」；界面对草稿与样例均有明示 |
| 成本 | 默认只自动生成 `RADAR_AUTO_GENERATE=0`（关闭）；每轮最多 3 条评估走模型 |
