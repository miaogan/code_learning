# r96 · 首页「今日计划」

## 1. 背景

r95 让计划跟日期对上了（起始日 → 今天是第几天 → 顺延），但**入口仍在报告页**：
用户每天打开产品先落在首页，看到的是画像与五步闭环卡，要跳到医案才知道今天该做什么。
计划已经知道「今天」，却只在一个需要主动想起的页面里说这件事。

## 2. 目标

1. 回访用户在首页就能看到**今天这一天的任务**、还剩几项、点哪里接着做；
2. 没开始计时 / 已过期的状态在首页也有明确出口（去医案开始 / 去医案重排）；
3. 与报告页**同一套判定**（复用 `planPace`），不出现「首页说第 3 天、报告页说第 4 天」；
4. 首页只读：不复制打卡写入路径，不产生第二套同步语义。

## 3. 不做

- 首页不做勾选打卡（唯一写入口仍是 `WeekPlan`，它带云端合并与防抖上推）；
- 不为首页新增接口：复用 `GET /api/reports/latest` + `GET /api/plans/{report_id}` + 本地阅读进度；
- 不推送提醒、不做日历订阅；
- 计划重算仍走 `buildStudyPlan` 确定性排程，首页不开检索引用（`citations` 只在报告页生成）。

## 4. 验收口径

| 编号 | 场景 | 期望 |
|---|---|---|
| AC-1 | 无报告 / 报告无薄弱地图 | 首页**整块不渲染**，不留空壳卡片 |
| AC-2 | 有报告但计划未开始 | 显示「还没开始计时」+「去医案开始 →」，不给假的 Day 1 |
| AC-3 | 进行中 | 标题「今日计划 · Day N」，meta「还剩 K 项」，列出今天的任务（未完成的下一项带高亮点），主按钮「接着做：<任务名>」 |
| AC-4 | 今天全做完 | meta「今天的 N 项都做完了」，不再给「接着做」按钮，保留「去医案看完整计划 →」 |
| AC-5 | 7 天走完 | meta「7 天已经过完，还有 N 天没做完」+「去医案看完整计划 →」，`day` 不给假值 |
| AC-6 | 接口失败 | 静默不渲染（首页是入口页，不弹错误条、不阻塞上传流程） |
| AC-7 | 打卡 / 成绩口径 | 首页不写任何状态；不产生打卡、成绩、熟练度、时间线数据 |
