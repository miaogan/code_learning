# r43 自检迭代 · PRD（不新开功能）

## 1. 背景与目标

合入前做一次自检：把「测试基线 / 测试瘦身判断 / 用户可感知的小缺陷 / 文档尾巴」四类技术债清到位，
**不开新功能、不改业务判定逻辑**。能做完几件算几件，不凑数。

## 2. 范围与优先级

| 优先级 | 事项 | 交付形态 |
| --- | --- | --- |
| P0 | 后端全量 `pytest` 基线 + 各文件耗时分布 | `TEST-BASELINE.md`（结果 + 分析） |
| P1 | 测试瘦身结论与方案（不贸然改） | `TEST-BASELINE.md` §3（先出结论，改动等确认） |

| P2 | `ARCHITECTURE.md` 文档尾巴 | 产品级文档更新 |

## 3. 验收口径

1. **AC-1 基线可见**：全量 pytest 结果（passed/failed/耗时）落盘，附 Top 耗时用例与各测试文件耗时分布。
2. **AC-2 瘦身有结论**：说清慢在哪（AI 是否真桩、有无真实等待、fixture 是否每次重建库），给可行方案与预期收益；**本轮不改**。
3. **AC-3 信息缺口只补一处**：卷面首行同时回答「过滤了什么 / 怎样回流 / 为什么仍有熟练题」；结果面板复显本卷事实；L2 兜底回流给「另有 N 道」。
4. **AC-4 小缺陷核对**：面试字数计数、405 中文化、上传上限单源逐条给证据；已交付的不重复改。
5. **AC-5 文档一致**：`ARCHITECTURE.md` 不再保留可证实已完成的「未落盘」条目；测试文件数与实际一致。
6. **AC-6 门禁**：前端四道门禁全绿；后端受影响文件 + `ruff` 全绿。
7. **AC-7 边界**：契约两侧同步、`snake_case`、错误 envelope 与闭集不破、样式只用 token、360–430 可用；不提交、不合并。

- 不改熟练度算法与阈值配置；
- 不改题库种子与组卷阶梯；
- 不做测试架构大改（只出方案）；
