# PRD · 在线练习题库与练习页（r11）

## 1. 背景与目标

### 1.1 现状（已读代码与数据确认，非推测）

- 题库：`backend/app/seed/questions.json` 共 **80 题**，`direction` 四值各 20 题（前端 / 后端 / 算法与数据结构 / 计算机基础）；`kind` = `single` 48 / `multiple` 20 / `text` 12；`difficulty` = basic 60 / intermediate 12 / challenge 8；`essentiality` = must_know 20 / advanced 20 / nice_to_know 40。**没有任何「语言」维度**，因此想练 `vue3` 或 `go` 只能练「前端/后端」这一锅混题。
- 存储：`questions` 表（`backend/app/db.py` DDL）承载题库，`services/question_bank.py` 是唯一读写入口（`_usable()` 可用性判定、`load_seed()`、`import_seed()` 幂等导入、`ensure_seeded()` 空库自种、`load_questions()` 组卷入口），SQL 只在 `repository.py`；种子文件是**唯一导入源**，运行时零 AI。
- 判分：`services/exam.py::grade_objective()` 纯本地集合相等判分（单选/多选，少选多选皆错，简答恒 False），答案只在服务端 `runs.payload`，响应模型 `ExamQuestion` 天然无 `answer`；客观题闭集单一出处在 `services/rules.py::is_objective_kind()`。
- 作答事件：`question_attempts`（`id, question_id, run_id, correct, answered_at, created_at`，`UNIQUE(question_id, run_id)`），由提交笔试卷一次写入；熟练度 `services/proficiency.py::evaluate()`（窗口 30 天、答对 ≥2 且最近一次正确=熟练，阈值只在 `config.py`）读同一张表，`proficient_ids()` 是组卷过滤唯一读侧入口。
- 前端：`App.tsx` 侧栏 = 5 步主线 + 「工具」组（`TOOL_ITEMS`：成绩趋势 / 简历润色）；无练习入口，无按语言筛选的页面。
- 结论：**题库缺语言维度与解析字段、缺判断题；产品侧缺一个「按语言精练」的入口**。笔试是「定位短板」，练习是「补短板」——后者当前不存在。

### 1.2 目标（可度量的结果）

1. 题库成为**语言可查询**的资产：9 个语言（python / java / go / html / css / js / ts / vue3 / react）**每个语言新增 20 道**，共 180 道新增；存量 80 题按**确定性规则**回填语言（无法归属则留空），全库总量 ≥260。
2. 题库**讲得清**：每道题（新增 180 道与存量 80 道均为强制项）都有正确答案与逐题解析（为什么对、错项错在哪），且被本地结构化校验脚本兜住（选项/答案/解析/去重/分布），一道不合格即门禁红。
3. 用户能**按语言精练**：`/practice` 按「语言 / 方向 / 难度 / 必备度」筛选 → 自选 10/20/全部 → 逐题作答（**单选 / 多选 / 判断**，本版只做选择题与判断题）→ 提交即出对错 + 正确答案 + 解析 → 下一题；支持「只看未做过 / 只看错题」。
4. 判分**零 AI、即时、同源**：练习与笔试共用同一个判分函数（不写第二套）；判断题以「两选项单选」结构落地，渲染与判分都不新增控件/判分分支；单题判分 ≤50ms、题单首屏 ≤300ms（本地 260 题量级）。
5. **练熟了就不该再考**：练习作答写入与 r6 同一套事件表与同一熟练度账本，练到阈值后笔试卷自动不再考该题；熟练度口径与组卷六级兜底零改动。
6. 既有能力零回归：笔试卷结构、报告证据链、多轮面试、成长时间线、简历润色、复制 Markdown、Docker 交付（服务名 `frontend`/`backend`、`WEB_PORT`、`skillcoach-data` 卷）全部保持可用。

## 2. 用户故事

**US-1（想练单独一门语言的开发者）** 我是写前端的，只想练 `vue3`，不想被 html/css 混题浪费时间。
- 验收条件：`/practice` 选「语言 = vue3」后，题单里 **100% 是 vue3 题**（接口响应与页面渲染双向断言）；再叠加「难度 = challenge」后只剩 vue3 且 challenge 的题；组合无结果时给中文原因与「放宽难度」建议，不白屏。

**US-2（要讲得通的练习者）** 我答错了要立刻知道**为什么错**，而不是只看到「答错」两个字。
- 验收条件：提交后同屏出现「对/错 + 正确答案 + 解析（非空中文，含错项为何不对）」；解析可折叠/展开；判断题解析必须说明该陈述**为什么对/为什么错**（不能只写"答案如上"）；全库 260 题 100% 有解析（结构化校验断言非空 ≥10 字）。

**US-3（要补短板的复练者）** 我想只做没做过的题，或者只把错题重练一遍。
- 验收条件：「只看未做过」返回的题当前用户**无任何作答事件**；「只看错题」返回的题**最近一次作答为错误**；两过滤器可与其他筛选组合、可清除；「错题重练」一键以错题为题单开新一轮。

**US-4（怕判断题含糊的作答者）** 判断题不能是「两个选项都说得通」的模糊陈述。
- 验收条件：判断题的陈述句只有唯一可判定真值，选项恰两个且 `answer` 指向其一，解析明确解释该陈述对/错的依据；抽检判断题（每语言 ≥2 道）无「陈述两可 / 与解析矛盾」的情况。

**US-5（反复练的用户）** 我把某题练熟了，笔试就别再考它；但**别因此让我出不了卷**。
- 验收条件：练习答对累计到阈值（30 天内 ≥2 次且最近一次正确）后，笔试卷候选池过滤掉该题（`filtered_count` 相应增加）；构造「全库熟练（含练习事件）」的极端情况，出卷仍 HTTP 200、≥10 题 / 客观 ≥8 / 挑战 ≤20%。

**US-6（产品/团队）** 题库是数据资产，标签不能靠手感。
- 验收条件：存量 80 题回填规则是**方向约束 + 关键词表 + 长词优先 + 未命中留空**的确定性算法（同输入两次运行结果字节相等，0 例语言-方向越界），回填结果表（每语言命中数 / 留空数）写入交付报告；新增 180 题每语言恰好 20 道且难度/题型/必备度分布落在闸门内。

## 3. 范围与非目标

### 3.1 本轮范围（只做这两件事）

1. **题库**：语言维度（含存量回填规则）、判断题题型（`judge`）、逐题解析、180 道新增语言题（seed JSON 固化 → 幂等导入）、本地结构化校验（脚本/测试）。
2. **练习页**：`/practice` + 侧栏工具组入口、四维筛选 + 范围（全部/未做/错题）+ 题量（10/20/全部）、逐题作答与即时判分/解析、错题本与错题重练、空态/错误态、契约双侧同步、移动端堆叠、UI 设计说明（DESIGN.md，先设计后开发）。

题库扩展方式是**扩展不取代**：r6 的四维（direction/kind/difficulty/essentiality）与组卷、熟练度口径一律保留；`language` 是**第五个筛选维度**，不参与组卷出题相关度；`kind` 闭集由 `single/multiple/text` 扩为 `single/multiple/judge/text`——判断题复用「两选项单选」结构，**不新增渲染控件、不新增判分分支**。

### 3.2 非目标（本轮明确不做）

- **填空题（blank）**：本版题库与练习页**只做选择题与判断题**，不做填空作答、不做填空判分与填空规范化比较（题目里可以有代码块，但没有填空输入框）。
- 闯关闭环、关卡地图、连胜/每日目标、积分成就、排行榜、社交/分享、题目评论。
- 真实代码执行判题（沙箱/编译器/测试用例运行），题目里可以有代码块，但**不执行用户代码**。
- 题库管理 UI（增删改题）、题目导入向导、题目审核工作流。
- 运行时用 AI 生成/改写题目；练习页任何路径调用模型（必须离线可用、秒开）。
- 多用户/账号体系；练习历史跨设备同步。
- 语言维度参与**笔试组卷的相关度/出题排序**（`language` 只作筛选维度；判断题是否进笔试卷面见 §11 第 1 条）。
- 学习路径推荐、课程与练习的联动编排、错题自动生成复习计划（留后续需求）。

## 4. anti-goals / 反面目标

> 以下每一条都「技术上能跑、测试能绿」，但会让人当场判定这东西不能上线。可被使用者直接观察。

1. **同一语言里刷到重复题**：归一化题干（去空白/全半角/标点后）相同或近似重复的两道题落进同一语言池，用户连续 10 题里看到第二次同一题面 → 直接判定「题库是凑数的」。可观察：任意语言内归一化题干重复数为 0。
2. **答案与解析互相矛盾 / 单选多解 / 判断题含糊**：单选正确项之外还有第二个选项在解析里被说成"也算对"；判断题陈述本身两可（如"Python 的 GIL 让多线程无法并行"这种没有限定条件的陈述），或解析讲的是另一个选项 → 用户按正确理解作答仍被判错，结论是「这题库不可信」。可观察：抽检 ≥30 题（每语言 ≥3，其中判断题每语言 ≥2）答案与解析逐条对得上；单选题与判断题 `answer` 恰 1 个 key，不存在"两个选项都成立"的题。
3. **提交前就泄露答案（伪练习）**：选项旁有暗示标记、页面源码/接口响应里带 `answer`/`explanation`，用户不思考点几下就刷完 → 练习失去意义。可观察：提交前题单响应的 JSON 与 DOM 中不含 `answer`/`explanation`/`correct` 字段（抓包与 Ctrl+U 自查）。
4. **筛选器骗人**：选了「python + challenge」，返回的题里混进 js 或 basic；或者筛出 0 题时页面白屏/只说"暂无数据"不说为什么 → 用户不知道是自己的筛选组合问题还是产品坏了。可观察：返回题 100% 命中筛选条件；空结果给中文原因 + 具体放宽建议。
5. **练一轮把笔试弄坏**：练完一批题后 `/exam` 出卷报 400 / 题数 <10 / 挑战题超 20%，或页面上「过滤了 N 道」没有任何解释 → 补短板的功能反而把主流程搞崩。可观察：练习作答 ≥30 道（含全部答对）后立即出卷仍 200 且结构闸门达标。

## 5. 交互流程摘要

```
侧栏「工具」→ 练习  (/practice)
  ├─ 筛选区：语言(9 选 1，含「全部/通用」) × 方向(4) × 难度(3) × 必备度(3)
  │          范围：全部 / 只看未做过 / 只看错题      题量：10 / 20 / 全部
  │          实时显示「当前组合命中 N 题」（0 题时给原因与放宽建议）
  ├─ 开始练习 → 题单逐题卡片
  │     题面（可含代码块）→ 单选/多选选项，或判断题的「正确 / 错误」两项
  │     提交后：✓/✗ 徽标 + 正确答案 + 解析（默认展开，可折叠）+ 进度（本次 x/N、正确 n）
  │     下一题 → 末题给完成态（本次正确率、去错题本 / 再来一轮 / 回筛选）
  ├─ 错题本：列表（题面摘要 + 语言/方向/难度 + 最近答错时间 + 答错次数）
  │           → 错题重练（以错题为题单开新一轮）
  └─ 空态：题库为空 / 筛选无结果 / 错题本为空 / 提交失败（中文 + 可操作出口，不白屏）
```

## 7. 验收标准（可在 CI/实跑中验证）

**AC-1 语言维度为第五维闭集，且方向归属单一出处**
`language` 闭集恰为 `("", "python","java","go","html","css","js","ts","vue3","react")`（空串 = 通用/算法类），前端侧 `{html,css,js,ts,vue3,react}`、后端侧 `{python,java,go}` 两组归属常量与方向映射**只写在 `services/rules.py` 一处**；`backend/app/schemas.py` 的 `QuestionLanguage` Literal 与 `frontend/src/api/types.ts` 的联合类型**逐字镜像**（静态门禁任一侧回退即红）；库内 0 例语言-方向越界，0 例闭集外取值。

**AC-2 存量 80 题回填是确定性算法，不是手感**
回填按「方向约束 → 关键词表（长词优先，命中即停）→ 未命中留空」执行：前端方向仅可能得到 `html/css/js/ts/vue3/react`，后端方向仅可能得到 `python/java/go`，算法与数据结构 / 计算机基础恒留空；**同一份种子跑两次结果字节相等**；`tests/` 内有 ≥8 条表驱动用例（含"前端方向关键词命中 python → 必须被方向约束拦下并留空"这类反例）；回填结果表（每语言命中数 + 留空数）写入交付报告；**不为凑数强行归属**，留空数量如实上报。

**AC-3 扩容与分布闸门（"每个语言 20 道"= 新增 20 道；题型只有单选/多选/判断）**
新增种子 `backend/app/seed/questions.json` 中，9 个语言**每个恰好 20 道（合计 180）**，且每语言满足：难度 basic 10–13 / intermediate 5–8 / challenge 2–4（合计 20）；**题型 `single` ≥12、`multiple` ≥3、`judge` ≥3（合计 20；新增语言题只用这三种，不得用 `text`，全库不得出现 `blank`）**；必备度 `must_know` ≥6、`advanced` ≥4；含代码块（三反引号围栏或缩进代码）的题 ≥2。全库：`算法与数据结构` 与 `计算机基础` 各仍 ≥20 道且 `language` 为空串；库存总量 ≥260。断言以「新增种子内每语言 == 20」为准（回填后某语言总数可 >20，不得为凑 20 删存量题）。

**AC-4 题面质量硬校验（一键可跑、失败即门禁红，必须覆盖判断题）**
新增 `tests/test_question_bank_quality.py`（或等价校验器）对**全库**断言：① `single` 的 `answer` 恰 1 个 key、`multiple` ≥2 个 key、**`judge` 的 `options` 恰 2 个且 `answer` 恰 1 个 key 并指向其中一个选项**；② 客观题 `answer` ⊆ `options[].key`（判断题含此约束）；③ 选项 2–6 个、key 唯一且为 A–F；④ 解析非空（去空白后 ≥10 字符，全库 260 题口径）；⑤ 同语言内归一化题干（去空白/全半角/标点归一后）重复数为 0；⑥ 上述 AC-3 分布闸门；⑦ `_usable()` 复核后全库可用题数 == 库存题数（坏行 0）；⑧ `kind` 闭集内不存在 `blank`。

**AC-5 新增字段走 DDL + repository，存量库自动升级**
`language` / `explanation` 字段：DDL 只在 `db.py`、SQL 只在 `repository.py`，路由/服务不出现裸 SQL；存量 `app.db`（含 r10 的 `skillcoach-data` 卷）在启动 `init_db()` 后**自动补列与补索引**，无需手工迁移（实跑：旧库启动 → 练习筛选 200 → 笔试出卷 200）；重复导入仍**恒 0 新增**、既有行不被覆盖（r6 AC-1 不回退）；新字段缺省为空串，读取侧不因缺字段抛错。

**AC-6 判断题口径与单一判分实现（本版无填空、无第二套判分）**
`judge` 加入客观题闭集（`rules.is_objective_kind()` 单一出处，与 `schemas.py`/`types.ts` 的 kind 联合类型逐字对齐）：题面为**陈述句**，`options` 恰两个（「正确」/「错误」），`answer` 指向其一；判分**复用既有 `grade_objective()` 的集合相等口径**（少选/多选仍算错），**全库只存在一个客观题判分函数**（静态断言：判分入口唯一、无第二个对比/归一实现），练习与笔试都调用它；判断题渲染走既有「单选」分支（`kind !== 'multiple'` 即单选项控件），**不新增控件分支、不新增判分分支**；全库 0 道 `blank`、0 处填空判分代码或归一化残留。

**AC-7 练习页筛选生效（服务端 + 页面双向）**
`/practice` 路由存在并挂在侧栏「工具」组（与 `成绩趋势`/`简历润色` 同组，样式与既有页一致，只用 `styles/tokens.css` 变量，**0 处裸色值**）；题单接口支持 `language / direction / difficulty / essentiality / scope(all|unseen|wrong) / limit(10|20|0=全部)`；**练习题单只收客观题 `kind ∈ {single, multiple, judge}`（`rules.is_objective_kind()` 单一出处），存量的 12 道 `text` 不进练习池，笔试对 `text` 的既有处理不变**；接口层断言「返回题 100% 命中全部筛选条件」，页面层断言「切换筛选后首屏题目语言/难度随之改变」；题量 10/20/全部生效（返回条数严格相等，除非命中不足，此时如实返回并给中文说明）；筛选 0 命中给「该组合下没有题目，试试放宽难度或必备度」类中文建议。

**AC-8 逐题作答与即时反馈（含解析展开）**
单选=`radio`、多选=`checkbox`、判断=`radio`（两项「正确/错误」，复用单选控件）；**未作答时提交被阻止或有明确中文提示**（不得直接出解析）；提交成功后同屏显示：对错徽标 + 正确答案 + 解析（默认展开，可折叠/再展开）+ 本次进度（x/N、正确 n）；「下一题」推进，末题给完成态（正确率 + 去错题本 / 再来一轮 / 回筛选）；一次会话内同一题不重复出现（题单去重）。

**AC-9 「只看未做过 / 只看错题」口径可验证**
`unseen` = 该题在 `question_attempts` 中**无任何事件**（练习与笔试共用同一张表 → 笔试做过的题也算"做过"）；`wrong` = 该题**最近一次作答为错误**；两者互斥、可切回「全部」，可与其他筛选叠加；接口用构造数据断言三条口径（未做/最近答错/最近答对后移出错题）；空结果显示中文空态。

**AC-10 错题本与错题重练可用**
错题列表包含：题面（截断展示，可展开）、语言/方向/难度、最近答错时间、答错次数，按最近答错时间倒序，支持按语言过滤；「错题重练」一键以当前错题为题单开新会话；重练答对后该题**移出错题本**（口径：最近一次答对即移出），答错仍在；接口与页面均有断言，含"错题本为空"中文空态。

**AC-11 作答落库，熟练度账本与笔试口径零改动**
练习作答写入**同一张 `question_attempts`**（`run_id` 用 `practice:<session_id>` 命名空间，保留 `UNIQUE(question_id, run_id)` 语义：同一会话同一题只记一条），并新增来源标识列（`source` = `exam`/`practice`，缺省 `exam`）供统计与将来区分；`proficiency.evaluate()` 阈值仍只在 `config.py`（窗口 30 天 / 答对 ≥2），本需求**不改判定公式**；回归断言：① 练习答对达阈值后笔试卷候选池过滤该题且 `filtered_count` 相应增加；② 构造「全库熟练（含练习事件）」时 `/api/exam` 仍 200、题数 10–12、客观 ≥8、挑战 ≤20%（r6 AC-2 / AC-3 不回退）；③ 组卷六级兜底阶梯代码零改动（`git diff` 可查）；④ 简答题（`text`）仍不参与熟练判定。

**AC-12 契约双侧同步与错误形态**
新端点（题单 / 单题判分 / 统计 / 错题本）在 `schemas.py` 与 `types.ts` **逐字对齐**（snake_case，含 `QuestionLanguage`、`PracticeScope`，以及 `kind` 联合类型新增的 `judge`），静态门禁（如 `test_r11_contract_mirror`）任一侧回退即红；错误统一 `{error:{code,message,retryable}}`，复用既有错误码闭集（不新增码：参数非法 = `VALIDATION_ERROR`，题不存在 = `NOT_FOUND`，未预期 = `HTTP_ERROR`），message 中文且不含路径/堆栈/端点/Key；筛选无结果**不是错误**（200 + 空列表 + 前端空态文案）。

**AC-13 空态与错误态（不白屏、不英文）**
五种状态各有中文提示与可操作出口：① 题库为空（提示"题库未就绪" + 重试）；② 筛选无结果（原因 + 放宽建议）；③ 题单加载失败（`InlineError` 中文原因 + 重试，按 r2 约定失败不得只用 Toast）；④ 提交判分失败（保留用户已选答案，可重试，不丢作答）；⑤ 错题本为空 / 会话完成。全部实跑截图或断言留证。

**AC-14 零回归门禁（只增不减）**
`python -m pytest -q` ≥368 通过（当前实跑 348 + 本需求新增 ≥20）；`npm test` ≥124 通过（当前 109 + 新增 ≥15）；`npm run typecheck` 0 error；`npm run lint` 0 error 且 ≤28 warning；`npm run build` 通过；`GET /health` 200；`/api/exam` 出卷与提交、`/api/report`、面试、`/api/timeline`、润色、复制 Markdown、`docker compose` 服务名/端口/卷约定全部保持可用（抽样回归）；`ruff` 若不可用需如实记录（r10 已记录环境限制）。

**AC-15 离线可用、运行时零 AI、时延达标**
练习全链路（题单/判分/统计/错题本）**零模型调用**：断言不触碰 `services/ai.py`、不读 Key、无 Key 环境（`AI_API_KEY` 置空）下全部 200（对比：画像类端点仍 503）；题库由 seed JSON 固化导入，运行时无 AI 生成；实测单题判分 P95 ≤50ms、260 题量级题单首屏 ≤300ms（本机 3 次取样）。

**AC-16 交付文档与 UI 设计说明（先设计后开发）**
任务夹内交付 `DESIGN.md`（练习页布局与栅格、筛选器形态（下拉/分段/芯片）与展开收起、解析默认展开+折叠交互、作答态与反馈态、390px 堆叠顺序、空态/错误态文案、无障碍焦点态）与 `TECHNICAL.md`（含**回填规则表**、**判断题落地口径**（陈述句书写规范与正反例 + 两选项 + 复用单选渲染与集合相等判分）、端点契约、DDL 变更与存量升级路径、`question_attempts` 取舍说明、字段-闭集单一出处清单）；`QA-REPORT.md` 含**各语言题量 + 难度/题型/必备度分布表**、**存量回填结果表（命中数/留空数）**、**「练习 vs 笔试共用同一题库」说明**（哪一层共享、哪一层刻意不同、为什么）、判断题抽检结论（陈述唯一真值、解析对得上），以及 AC-7/AC-8/AC-9/AC-10 的实际请求与响应证据。

**AC-17（P1）390px 移动端可用**
390px 视口下：筛选器纵向堆叠、代码块可横向滚动但**页面本身无横向滚动**、解析展开不溢出、提交/下一题按钮 40 高且可点、无文字裁切；断言方式：视口截图 + 页面 `scrollWidth <= clientWidth` 检查。

**AC-18（P1）练习进度可见**
练习页显示「本次 x/N、正确 n、正确率」，并显示全库「已练 m / 总题数 M」（m = 有作答事件的题数）；刷新页面后本次会话统计允许重置（不新增表、不做跨刷新持久化），但全库已练数必须来自服务端真实数据。

## 8. 依赖与风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 存量 `app.db`（Docker 卷 `skillcoach-data`）没有 `language`/`explanation` 列 | 升级后读库报错、练习筛选全空 | `init_db()` 幂等补列（`PRAGMA table_info` 判定 + `ALTER TABLE`），AC-5 实跑旧库启动验证；`.dockerignore`/卷约定不动 |

## 11. 假设与待澄清

- （taste）**判断题是否进入笔试卷面**：本版**选定「进」**——判断题就是两选项单选，渲染走既有单选分支、判分仍走 `grade_objective()` 的集合相等，理论上 `ExamPage` 零改动，还能让笔试多一种题型；同时设**降级闸门**：实施时若实测 `ExamPage` 必须改 kind 分支才能正确渲染判断，则本版判断题**不进制**，以「笔试页零改动」为最高优先（届时 `judge` 只进练习池）。两种结局都不新增错误码、不改判分实现。
- （taste）**存量 80 题是否补齐解析**：默认**补齐**（全库统一"解析非空 ≥10 字符"校验，否则练习抽到存量题时解析区是空的，体验残缺，且 anti-goal 2 无从检验）；替代方案是只要求新增 180 道有解析、存量题显示"本题暂无解析"降级文案。本版按用户「存量 80 题补齐逐题解析」的明确要求执行。
- （taste）**练习事件是否按原阈值计入熟练度**：默认**按原阈值（30 天 ≥2 次且最近一次正确）计入同一账本**（用户明确要求"练熟了就不该再考"）；风险是练习可高频重复作答，可能比笔试更快把题标熟、使笔试候选池提前走兜底阶梯。替代方案：练习事件独立计数（如要求 ≥3 次）或练习事件只记录不参与熟练判定——都需要改 `proficiency.py` 口径，属改基线，须另立需求。
- （taste）**错题本口径**：默认「最近一次作答错误即入、答对即移出」（与"错题重练"的闭环一致）；替代方案是保留历史曾答错记录（题做完不再错也仍留在错题本，需要"手动移除"）。
- （taste）**新增 180 道的知识深度**：默认「语言核心 + 最主流框架/工具链基础」（框架题每语言 ≤5 道、其余考语言本身：语法/语义/常见陷阱/标准库/构建工具），难度以 basic 为主；替代方案是大幅偏框架（更贴岗位 JD，但与"基础课程"的补短板定位偏离）。
- （taste）**练习页默认题量与解析呈现**：默认题量 **10**、解析**默认展开**（要求"提交后立即显示逐题解析"）；替代方案是默认 20 题、解析默认折叠（先看对错再展开）。
