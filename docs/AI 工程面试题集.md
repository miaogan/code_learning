- B. 是否需要固化领域风格 / 降低高频调用成本 ✅
- C. 提示 + 检索是否已能稳定达标 ✅
- D. 仅看 GPU 是否空闲

**答案**：A、B、C　**解析**：微调有数据、算力与维护成本；当提示+检索已达标时不必微调；只有数据齐备且确有收益才上。

### Q150. 【单选 · 挑战 · 进阶】 大模型服务偶发超时（每秒几次），最稳健的客户端处理是？

- A. 指数退避 + 抖动做有限重试，并切备用/更小模型兜底 ✅
- B. 立即无限重试直到成功
- C. 直接抛出异常让请求崩溃
- D. 忽略超时继续往下走

**答案**：A　**解析**：偶发超时用有限退避重试 + 降级兜底最稳；无限重试会放大负载、崩溃/忽略则损害可用性。

### Q151. 【多选 · 挑战 · 进阶】 评估一个 RAG 系统上线前的质量，应当覆盖哪些维度？

- A. 检索质量：命中率(Hit Rate)/MRR/NDCG ✅
- B. 生成质量：忠实度(Faithfulness)与答案相关性 ✅
- C. 端到端线上信号：采纳率/会话完成率 ✅
- D. 只统计生成速度，不衡量检索质量与生成质量

**答案**：A、B、C　**解析**：RAG 评测需检索、生成、线上三层覆盖；仅看速度无法反映答案好坏。

### Q152. 【单选 · 进阶 · 必会】 团队要为一个新业务接入 LLM，第一步最该做的是？

- B. 直接把全部业务数据喂给模型

### Q153. 【多选 · 挑战 · 进阶】 提示词（Prompt）上线后出现效果漂移（同样的 prompt 不同时间结果变差），可能原因与对策包括？

- A. 模型版本/系统提示被静默更新 → 固定模型版本并做回归评测 ✅
- B. 上游依赖（检索/工具）变化 → 加监控与集成测试 ✅
- C. 把 temperature 设为 0 即可彻底排除所有漂移
- D. 无监控无基线 → 建立评测基线与告警 ✅

**答案**：A、B、D　**解析**：漂移多来自上游静默变更或缺乏基线；temperature=0 只降随机性，不能消除外部变更导致的退化。

### Q154. 【判断 · 挑战 · 进阶】 生产环境可以不做任何评测基线，等问题出现再修复即可。

- A. 正确
- B. 错误 ✅

**答案**：错误　**解析**：没有基线与监控，退化会被延迟发现且难以定位；LLM 应用应“上线即带评测与告警”。

### Q155. 【单选 · 挑战 · 进阶】 你接到需求“让 Agent 自动处理用户退款”，从安全角度最该先确认的是？

- A. 退款是否需 human-in-the-loop 确认，以及权限/额度/审计控制 ✅

- C. 只看模型能否生成合法 JSON

### Q156. 【多选 · 挑战 · 进阶】 为 LLM 服务做容量规划，需要考虑哪些？

### Q157. 【单选 · 挑战 · 进阶】 你想用 LLM 从非结构化简历中抽取结构化字段，最稳妥的工程方案是？

- A. 结构化输出(JSON/Function Calling) + 字段校验与重试 + 抽样人工复核 ✅
- B. 直接用正则解析非结构化文本
- C. 让模型自由文本输出后再人工逐条读
- D. 关闭校验直接入库
